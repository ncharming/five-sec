# Spec: 单次待办默认提醒（specs/013）

## 背景

「单次」待办（specs/007）被视为**必须今天完成**的任务——它只有一天有效期，错过即失败进过期区。
010 的到点提醒是可选配置（单时刻 `HH:mm`、默认关），对「单次」这种强到期语义的条目，默认无提醒
等于关键任务静默滑过。本 spec 给单次待办一个**强制性的到期提醒默认**，并顺带把提醒列从单时刻
泛化为多时刻（单次需要的就是多个时刻）。

## 需求（用户原始口径）

1. 新建「单次」类型的待办时，默认自动添加三个提醒时间点：**当天 20:00、21:00、22:00（整点）**。
2. 提醒触发时双通道提示：应用内弹窗（类闹钟全屏提醒页）+ 手机系统通知栏通知。
3. 待办标记「已完成」后，取消其剩余全部提醒——后续时刻不再弹窗、不再通知。

## 方案

- **多时刻编码（零迁移）**：`todos.reminderTime` 列从单值 `HH:mm` 扩展为逗号分隔列表
  （规范形 = 升序去重、上限 `MAX_REMINDER_TIMES = 3`）。列定义（TEXT NOT NULL）不变 →
  Room schema/版本零变更、存量单值即单元素列表。读写/校验/排程统一收进
  `TodoReminderPlanner`（`parseReminderTimes` / `isValidReminderTimes` / `normalizeReminderTimes`）。
- **默认三时刻**：`DEFAULT_ONCE_REMINDER_TIMES = 20:00/21:00/22:00`。弹窗规则段**切到「单次」且
  当前无时刻时预填**（用户可见、可增删改、可清空）；离开单次且预填**原封未动**则还原为空
  （`timesOnRuleSwitch` 纯函数，单测覆盖）。仓库**只认传入值**——用户清空后保存 = 明确不提醒
  （默认 ≠ 不可关，尊重显式关闭）。
- **双通道触发（复用 010，零新增链路）**：到点 → 响铃前台服务（铃声+震动）→ FSI 通知（通知栏
  载体）+ 全屏提醒页 `TodoReminderActivity`（应用内类闹钟弹窗，息屏直拉/亮屏补拉）。多时刻经
  `isDueForMinute` 的「分钟 ∈ 列表」判定天然接入。
- **完成即取消（复用 010，零新增链路）**：响前查库（`lastCompletedDate != reminderDay`）+ 
  observeAll 收集器自动重排——勾掉完成瞬间，当日剩余时刻在判定层整体静默、闹钟重排自动跳过。

## 验收

- 新建单次待办（不碰提醒区）→ 保存后提醒设置显示 20:00、21:00、22:00 三时刻，行内角标
  「提醒 20:00、21:00、22:00」；
- 到达任一提醒时刻且未完成 → 全屏提醒页与系统通知同时触发（息屏/亮屏均响铃震动）；
- 标记完成后 → 后续时刻（21:00、22:00）均不再触发弹窗与通知。

## 红线沿用

提醒不写任何事件表、不进统计（010）；`interception_events` 只增不删；纯离线无新增权限。
