# Spec: 回弹层停留预算（specs/015）

## 背景

specs/012 的回弹层只说「本场停留 M 分钟」——单场感知回答不了「我今天刷了多少」。本 spec 给
会话守护加**每日停留预算**：全局一个数字（分钟，默认关），回弹层在单场时长之外追加「今日累计」，
超预算时视觉升级。让 012 的二次减速带从「单场检查点」升级为「全天用量仪表」。

前置依赖：2026-11 会话心跳修复（否则今日累计建立在漏记数据上）。

## 需求

1. 设置页守护卡内新增「每日停留预算」行：预设直选 30/60/90/120/180 分钟 + 「不设」（默认）；
   DataStore `stay_budget_minutes`（0=不设，夹取 0..600）。
2. 回弹层副行从固定文案升级为双段：今日累计 + 预算——「今日已停留 X 分钟（预算 B）」；
   未设预算时保持现有副行文案不变。
3. 超预算时（累计 ≥ 预算）：「结束」按钮文案不变但整卡顶部追加一条品牌红警示行
   「已超出预算 N 分钟」，并再震一次（60ms）。
4. 预算是**全局单值**（不分应用）：刷的时间是同一条命，分应用预算徒增配置面。

## 方案

- **DataStore**：`SettingsDataStore` 加键 `stay_budget_minutes`（默认 0=不设），`AppSettings` 增字段；
  档位弹窗沿用守护间隔的 FiveSecDialog 预设直选模式。
- **今日累计的读取口径**：会话开启（`onOpened`）时异步预取「今日该应用已落库会话 SUM」进服务
  `@Volatile` 字段（回弹最早也在 N≥5 分钟后发生，预取必然就绪）；回弹层展示 = 预取值 + 本场
  elapsed（墙钟，与标题分钟同源）。预取失败回退「仅本场」（宁可少说不虚报）。
- **纯逻辑**：`util/StayBudget`（预算行文案格式化 + 超额判定 + 超额分钟数），单测覆盖
  （未设/未超/恰好/超出）。
- **UI**：`UsageGuardOverlay` 副行改造 + 超额警示行；`InterceptScreen` 守护卡加预算行。

## 验收

- 预设 60 分钟：当天先刷两场各 25 分钟（都选继续），第三场第 15 分钟回弹 → 副行「今日已停留 65 分钟（预算 60）」+ 顶部红行「已超出预算 5 分钟」+ 弹出短震两次（弹出一次 + 超额一次）；
- 未设预算：回弹层与现状完全一致；
- 切「不设」即时生效（下一场回弹不再显示预算段）。

## 红线沿用

预算不写任何事件表、不进统计；会话表照旧 append-only；纯离线零新权限；FR-014 随时可关
（预算只是展示层强化，「继续」永远可用）。
