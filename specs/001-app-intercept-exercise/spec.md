# Feature Specification: App Launch Interceptor with 5-Second Exercise Prompt (五秒 / five-sec)

**Feature Branch**: `001-app-intercept-exercise`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "我想做一个 Android 手机的 app，在打开小红书、抖音、B站等应用时会弹窗拦截提示你是否需要打开，弹窗拦截的时候会从提示提肛5s。以此让用户可以做一些日常马上就能做的锻炼，并且减少用户对流量app的使用程度"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 拦截目标应用并引导 5 秒提肛 (Priority: P1)

当用户点击打开一个被列入"目标应用"的流量/沉浸类应用（如抖音、小红书、B站）时，应用会拦截这次启动，先弹出一个全屏覆盖层。覆盖层中同时做两件事：引导一次 5 秒钟的提肛（凯格尔）锻炼，并询问用户"是否真的要打开这个应用"。

**Why this priority**: 这是产品最核心、最具定义性的功能，没有它就没有产品。它在一个交互里同时达成两个目标——完成一次日常微锻炼，并在打开沉浸式应用前制造一个"减速带"式的停顿，从而减少无意识使用。

**Independent Test**: 把抖音加入目标应用列表，点击抖音图标，验证：在抖音真正打开之前，会出现带 5 秒提肛引导的拦截弹窗。

**Acceptance Scenarios**:

1. **Given** 抖音在目标应用列表中且拦截已开启，**When** 用户点击抖音的启动图标，**Then** 在抖音打开之前出现一个拦截弹窗，显示 5 秒提肛锻炼引导和"是否打开抖音？"的询问，且抖音此尚未打开。
2. **Given** 拦截弹窗正在显示且 5 秒倒计时进行中，**When** 用户尝试点击"打开"或"取消"，**Then** 这些选择处于锁定（不可用）状态，必须等待 5 秒倒计时结束。
3. **Given** 拦截弹窗正在显示，**When** 5 秒倒计时结束，**Then** "打开"和"取消"按钮变为可用，用户能够做出选择。
4. **Given** 倒计时已结束且按钮可用，**When** 用户选择"取消"，**Then** 抖音不打开，用户回到点击之前所在的位置。
5. **Given** 倒计时已结束且按钮可用，**When** 用户选择"打开"，**Then** 抖音正常打开。

---

### User Story 2 - 自行配置被拦截的应用列表 (Priority: P2)

用户可以添加或移除哪些应用会被拦截，并能全局开关或针对单个应用开关拦截。

**Why this priority**: 用户提到的应用只是举例（"等应用"）；要让工具对默认列表之外的应用也有用，用户必须能自行管理这份清单。

**Independent Test**: 添加一个不在默认列表里的应用（如微博），打开它，验证拦截弹窗出现。

**Acceptance Scenarios**:

1. **Given** 用户在设置页，**When** 用户把微博加入目标列表，**Then** 打开微博会触发拦截弹窗。
2. **Given** 微博已在列表中，**When** 用户移除微博，**Then** 打开微博不再触发拦截。
3. **Given** 全局拦截已开启，**When** 用户单独关闭对 B站 的拦截，**Then** 打开 B站 不触发拦截，但其它列表内应用照常拦截。
4. **Given** 用户想暂停整个工具，**When** 用户切换全局总开关为关，**Then** 在重新开启前，任何应用都不被拦截。

---

### User Story 3 - 查看每日锻炼与拦截情况 (Priority: P3)

用户能看到简单的统计：今天被拦截了多少次、其中多少次选择了"取消"而非"打开"，以及连续完成 5 秒锻炼的天数（打卡连击）。

**Why this priority**: 用轻量的反馈强化习惯养成和"减少使用"的目标，但不是核心价值所必需。

**Independent Test**: 触发若干次拦截并做出不同选择，验证统计页能正确反映这些次数。

**Acceptance Scenarios**:

1. **Given** 用户今天触发了 3 次拦截并取消了其中 2 次，**When** 用户打开统计页，**Then** 显示今日 3 次拦截、2 次取消。
2. **Given** 用户连续若干天都完成了 5 秒锻炼，**When** 用户打开统计页，**Then** 连续天数（streak）正确反映这些天。

---

### Edge Cases

- 用户从通知或深层链接（deep link）打开目标应用时（而非从桌面图标），拦截是否仍然生效？预期行为需要明确。
- 用户反复点击"打开"或尝试绕过弹窗时如何处理？
- 来电期间、或另一个全屏应用正在前台时，拦截弹窗应如何表现？
- 用户拒绝或撤销了所需的权限（应用启动检测或覆盖层显示）时如何提示与降级？
- 5 秒倒计时被打断（息屏、按 Home）时如何处理？
- 拦截机制会频繁运行：后台资源占用（电量、性能）如何最小化，避免用户可感知的耗电？
- 首次使用时所需的权限需要被请求并向用户解释清楚。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 能检测到用户尝试启动"目标应用列表"中的任意应用。
- **FR-002**: 系统 MUST 在目标应用打开之前，显示一个拦截覆盖层弹窗，该弹窗同时 (a) 引导一次 5 秒提肛（凯格尔）锻炼，并 (b) 询问用户是否要打开该应用。
- **FR-003**: 系统 MUST 允许用户选择"打开"目标应用，或"取消"并返回到点击之前的界面。
- **FR-004**: 系统 MUST 提供一份默认目标应用列表（涵盖常见的沉浸式内容应用：短视频 / 社交 / 图文社区类，如抖音、小红书、B站 等），并 MUST 允许用户向列表中添加或移除应用。
- **FR-005**: 系统 MUST 允许用户全局开启/关闭拦截，以及针对单个应用开启/关闭拦截。
- **FR-006**: 在拦截弹窗中，5 秒锻炼倒计时期间 MUST 锁定"打开/取消"选择（强制 5 秒减速带模式）；只有当 5 秒倒计时结束后，"打开"和"取消"按钮才变为可用，用户才能做出选择。这是产品的核心性格：每一次拦截都强制制造一次完整的 5 秒暂停与提肛锻炼。
- **FR-007**: MVP 中拦截弹窗的锻炼内容 MUST 固定为"5 秒提肛（凯格尔）"这一项（与应用名"五秒 / five-sec"一致）；其它微锻炼种类（远眺放松、深呼吸、端正姿势等）不在 MVP 范围内，留待未来版本扩展。
- **FR-008**: 系统 MUST 提供首次运行的权限引导流程，请求并解释完成"应用启动拦截"和"覆盖层显示"所需的各项权限。
- **FR-009**: 系统 MUST 在本地（设备端）记录简单的拦截日志（应用、时间、是否完成锻炼、打开/取消的选择），供统计页使用。
- **FR-010**: 系统 MUST NOT 要求任何账号、登录或网络连接即可使用核心功能。
- **FR-011**: 系统 MUST 允许用户随时完全关闭拦截（或卸载），且绝不会因为本工具而无法进入自己的应用。

### Key Entities *(include if feature involves data)*

- **Target App（目标应用）**: 一个被选为拦截对象的已安装应用（标识、显示名称、是否对该应用开启拦截）。
- **Interception Event（拦截事件）**: 一次用户尝试打开目标应用的记录，含目标应用、时间戳、是否完成 5 秒锻炼、用户的打开/取消选择。
- **Exercise（锻炼项）**: 拦截时展示的 5 秒微锻炼（类型与引导文案；默认为提肛）。
- **App Settings（应用设置）**: 全局总开关、默认列表配置及其它用户偏好。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 当用户点击目标应用的桌面图标时，超过 95% 的情况下会在该应用打开之前出现拦截弹窗。
- **SC-002**: 从点击目标应用图标到拦截弹窗可见且可读，至少 90% 的情况下延迟在 1 秒以内。
- **SC-003**: 5 秒锻炼引导对用户清晰可读、可计数（可见的从 5 到 0 的倒计时）。
- **SC-004**: 首次使用的用户能在 3 分钟内完成权限设置并添加第一个目标应用。
- **SC-005**: 在为期一周的试用中，用户至少在 30% 的拦截中选择了"取消"（不打开），表明使用意愿被有效降低。
- **SC-006**: 安装并保留本工具一周的用户中，至少 70% 报告它帮助自己至少完成了一次日常微锻炼。
- **SC-007**: 工具的后台/拦截机制在日常使用中不产生用户可感知的额外耗电。

## Assumptions

- 目标用户是希望减少在沉浸式内容应用上耗时、和/或希望建立日常微锻炼习惯的 Android 手机用户。
- 目标用户愿意在首次运行时授予完成"应用启动拦截"和"覆盖层显示"所需的权限。
- 所有数据均存储在设备本地；v1 不包含后端、账号或云同步。
- 默认目标应用列表反映国内常见的沉浸式内容应用（抖音、小红书、B站 及同类），用户可编辑该列表。
- 拦截对象是用户安装的第三方应用；v1 无需拦截系统必备应用（电话、短信等）。
- 锻炼时长固定为 5 秒，与应用名"五秒 / five-sec"一致。
- "提肛"（凯格尔/盆底肌）是首要/默认锻炼项；是否引入更多锻炼种类由 FR-007 的澄清结果决定。
- v1 仅面向 Android 单平台；其它平台不在范围内。
- "流量 app / 沉浸式应用"指短视频、社交、图文社区等容易让人无意识长时间使用的内容类应用。
