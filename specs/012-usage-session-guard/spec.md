# Feature Specification: 使用时长守护（二次减速带）

**Feature Branch**: `012-usage-session-guard`

**Created**: 2026-10-10

**Status**: Draft

**Input**: 用户认可的演进方向——现有产品只对「入口」征税（5 秒减速带），选「打开」后刷 1 小时也不会再有任何摩擦：5 秒税对长会话太便宜。本 spec 补「停留时长」维度：选「打开」即开始会话，连续停留满设定时长（默认 15 分钟）且仍在该应用时，弹**回弹覆盖层**「已在 X 停留 M 分钟」，提供「继续 N 分钟 / 结束」；会话结束落一行 `usage_sessions` 事件（append-only），统计侧新增「停留 N 分钟」。零网络、零新依赖，`interception_events` 契约零触碰。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 连续停留满时长回弹（Priority: P1)

用户在拦截页选「打开」进入抖音，连续刷满 15 分钟（可配置 5–60）：屏幕上弹出全屏回弹层——「已在 抖音 停留 15 分钟」+ 副句「休息一下，看看今天还有什么没做」+ 今日待办卡 + 「继续 15 分钟」（主按钮）/「结束」（次按钮）+ 一次短震。**无 5 秒倒计时**（入口减速带才强制等待；回弹是检查点不是闸门），按钮立即可点。中途切走（回桌面/别的应用）计时即取消，切回后重新计满整段。

**Why this priority**: 本功能的核心价值——把「只管入口」补成「入口 + 停留」双摩擦，专治「就刷 5 分钟」变成 1 小时。

**Independent Test**: 回弹间隔设 5 分钟 → 拦截后选「打开」→ 在抖音停留 5 分钟不切走 → 回弹层弹出（标题、待办卡、两按钮、短震）；中途切走 2 分钟再回 → 从切回重新计 5 分钟。

**Acceptance Scenarios**:

1. **Given** 守护开启（默认）且选「打开」进入目标应用，**When** 连续停留满 N 分钟，**Then** 弹回弹层：标题「已在 X 停留 M 分钟」（M=本场自打开起墙钟，向上取整）、副句、今日待办卡（009 四态同款）、「继续 N 分钟」实心 +「结束」文字按钮、60ms 短震。
2. **Given** 计时中切到其他应用/桌面，**When** 切走瞬间，**Then** 计时取消；**When** 再切回目标应用，**Then** 重新计满整段 N 分钟（连续停留口径，非累计）。
3. **Given** 回弹层已弹出，**When** 点「继续 15 分钟」，**Then** 撤层回到应用原地、重装 N 分钟计时。
4. **Given** 回弹层已弹出，**When** 点「结束」，**Then** 回桌面（先 HOME 再延迟 250ms 撤层，反闪现契约沿用）、本场放行标记清除（再次进入走完整入口减速带）、会话以 GUARD_ENDED 落一行。
5. **Given** 该应用守护关闭（⋯菜单「时长守护」），**When** 打开后任意停留，**Then** 永不回弹，但会话照常记录（使用时长统计不受开关影响）。

---

### User Story 2 - 回弹频率上限：不打扰到被卸载（Priority: P1)

每场会话最多回弹 **3 次**；第 3 次选「继续」后本场不再打扰（计时器不再装）。会话结束后（结束/闲置超时/被新会话取代）计数重新开始。

**Why this priority**: 无上限的回弹会把守护变成弹窗机器——用户会去关无障碍而不是少刷；上限让产品保持「提醒」而非「管制」的性格。

**Independent Test**: 间隔 5 分钟 + 连续选「继续」三次 → 第四次满 5 分钟不再弹；回桌面 30 分钟后重开应用 → 又开始回弹。

**Acceptance Scenarios**:

1. **Given** 同一场会话已回弹 3 次且都选了「继续」，**When** 再次停留满 N 分钟，**Then** 不再弹层、不再计时（本场静默）。
2. **Given** 会话因任意原因结束（结束/闲置/新会话取代/服务销毁），**When** 用户重新选「打开」开始新会话，**Then** 回弹计数从 0 重置。

---

### User Story 3 - 会话记录与停留统计（Priority: P2)

每场会话结束时写一行 `usage_sessions`（append-only 单行 INSERT，无 UPDATE）：包名、开始/结束时刻、时长（毫秒）、回弹次数、结束原因。统计页「应用拦截统计」二级页每个应用卡新增「停留 N 分钟」（所选周期内 SUM，分钟向上取整，>0 才显示）。

**Why this priority**: 停留时长首次可见——「拦截 12 次、停留 6.5 小时」比单看拦截次数更接近真相；也是后续「省下时间估算」的数据基础。P2 因为它是记录侧，不改变行为回路。

**Independent Test**: 今天抖音会话 20 分钟 + 40 分钟 → 拦截二级页「日 · 今天」抖音卡出现「停留 60 分钟」。

**Acceptance Scenarios**:

1. **Given** 任一会话结束（GUARD_ENDED/SUPERSEDED/IDLE_TIMEOUT/SERVICE_STOPPED），**Then** 恰好新增一行 usage_sessions，已有行不更新不删除。
2. **Given** 周期内某应用有多场会话，**When** 看拦截二级页，**Then** 应用卡显示「停留 N 分钟」（按 endedAt 落入周期聚合）。
3. **Given** 周期内无会话，**Then** 不显示停留行（0 不展示，与「零是有效数据」并行：这里无行=无会话，展示留白）。

---

### User Story 4 - 配置：全局回弹间隔 + 每应用开关（Priority: P2)

设置页新增「使用时长守护」卡：说明文案 + 「回弹间隔」行（点击弹预设选择：5/10/15/20/30/45/60 分钟，默认 15，DataStore 持久化）。每个目标应用 ⋯ 菜单新增「时长守护」开关（target_apps 列，默认开）——B 站看学习内容等场景可单关。

**Why this priority**: 15 分钟不是普适真理（学习型目标应用与纯消遣应用节奏不同）；但配置面必须极小——一个全局数字 + 每应用一个布尔，拒绝更多设置项。

**Independent Test**: 设置页点「回弹间隔 · 15 分钟」→ 弹预设 → 选 30 → 行变「30 分钟」；⋯菜单关掉 B 站「时长守护」→ B 站不再回弹、抖音照常。

**Acceptance Scenarios**:

1. **Given** 设置页，**When** 点回弹间隔行选 30，**Then** 持久化生效（重启后仍是 30）；下次装计时用新值（已装的计时不受追改）。
2. **Given** B 站守护关闭、抖音开启，**When** 两者都满时长停留，**Then** 只有抖音回弹；两场会话都照常记录。
3. **Given** 全新安装/存量用户升级，**Then** 全部应用守护默认开、间隔默认 15 分钟（升级零感知，除多了回弹行为本身）。

---

### Edge Cases

- **息屏在目标应用内到点**：无窗口事件、前台判定仍为该应用 → 照常弹层（无障碍覆盖层可显示于锁屏之上），解锁即见；不补弹也不跳过。
- **回弹与拦截错峰**：回弹层显示期间忽略一切拦截事件（含去抖判定）；切到其他目标应用会先取消会话计时再走拦截，二者天然互斥、无双层叠窗。
- **回弹层 addView 失败**（OEM 拦截/窗口异常）：本场停止守护（不再重试），会话照常记录到结束；绝不闪退。
- **进程被杀/服务被拆**：onUnbind/onDestroy 尽力落 SERVICE_STOPPED 行；直接被杀则本场丢失——**只低估不高估**，可接受。
- **闲置关闭**：离开会话应用 ≥30 分钟（惰性判定：下一次前台切换事件时检查），会话以 IDLE_TIMEOUT 关闭、endedAt=最后停留时刻（时长不含离开后时间）。
- **时长口径**：duration = endedAt − startedAt 墙钟（含中途短暂离开），命名为「会话时长/停留」而非「净使用」；连续停留计时（回弹判定）与墙钟时长（统计）是两个口径，文档与 UI 措辞区分。
- **运行中改配置**：间隔/开关在**下一次装计时**生效——已装计时不追改；关闭守护不关会话（记录继续），重开则下次切回该应用时恢复计时。
- **拦截总开关关闭**：不再产生新会话；已开会话继续守护至正常结束（守护的是「已放行的使用」）。
- **升级迁移**：v11→v12——target_apps 加 sessionGuardEnabled（默认 1，存量全开）、新建 usage_sessions 空表；正式 Migration + 手建库迁移测试，无破坏性操作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 选「打开」MUST 开启会话（该应用获得既有 userOpenedPkg 放行，语义零改动）并装回弹计时；计时 MUST 只在「当前前台 == 会话应用」期间有效——切走即取消、切回重装整段 N 分钟（连续停留口径）。
- **FR-002**: 停留满 N 分钟且前台仍为会话应用时 MUST 弹回弹层：标题（应用名 + 本场墙钟分钟数，向上取整）、副句、今日待办卡（与拦截覆盖层同源同四态）、「继续 N 分钟」主按钮、「结束」次按钮、60ms 单次震动；MUST NOT 有 5 秒倒计时、MUST NOT 写 `interception_events`。
- **FR-003**: 「继续」MUST 撤层并重装 N 分钟计时；「结束」MUST 按「先 HOME 再延迟 250ms 撤层」契约回桌面、清 userOpenedPkg/suppressedPkg、会话以 GUARD_ENDED 落库。
- **FR-004**: 每场会话回弹 MUST 上限 3 次，达上限后选继续则本场静默（不再计时不再弹）；会话结束计数重置。
- **FR-005**: 会话结束 MUST 恰好新增一行 `usage_sessions`（INSERT-only）：结束原因四选一 GUARD_ENDED/SUPERSEDED/IDLE_TIMEOUT/SERVICE_STOPPED；闲置阈值 30 分钟（endedAt=最后停留时刻）；表 MUST 只增不删。
- **FR-006**: 判定逻辑 MUST 在零 Android 依赖的纯类（`interception/UsageSessionTracker`）中，服务只做事件路由与动作执行（ArmTimer/CancelTimer/CloseSession）；时间 MUST 经注入 TimeProvider；MUST 配状态机单测矩阵。
- **FR-007**: 配置：全局回弹间隔 DataStore `session_guard_minutes`（默认 15，夹取 5–60，预设 5/10/15/20/30/45/60）；每应用 `target_apps.sessionGuardEnabled`（默认开，⋯菜单切换）；配置变更在下次装计时生效。
- **FR-008**: 迁移 MUST v11→v12 正式 Migration（加列默认 1 + 建 usage_sessions 表）配手建库测试；MUST NOT 破坏性迁移、MUST NOT 触碰 `interception_events`/`todos`/`todo_completions` 任何行为。
- **FR-009**: 统计二级页应用卡 MUST 新增「停留 N 分钟」（周期内 SUM(durationMillis)、按 endedAt 半开区间归期、分钟向上取整、>0 才显示）；MUST NOT 改动今日卡/时段分布既有锚点。
- **FR-010**: 拦截链路既有契约 MUST 零回归：减速带状态机、成功态（011）、待办卡四态、三个放行标记优先级、去抖/抑制窗口——一行不改语义；MUST NOT 引入网络/分析依赖。

## Success Criteria *(mandatory)*

- **SC-001**: 间隔 5 分钟实测：打开 → 连续停留 5 分钟弹层（标题分钟数正确）→ 继续 → 再 5 分钟再弹 → 如此三次后静默；切走重进重计。
- **SC-002**: 结束路径：回弹层点「结束」→ 回桌面不闪现目标应用 → 再进目标应用走完整 5 秒减速带；usage_sessions 落 GUARD_ENDED 行。
- **SC-003**: 关 B 站守护 → B 站满时长不弹但会话照记；改间隔 30 → 下场会话 30 分钟才弹；重启后配置保持。
- **SC-004**: 拦截二级页应用卡「停留 N 分钟」与实际会话总和一致（跨周期切换正确）；无会话不显示。
- **SC-005**: 存量用户升级：数据零丢失（迁移测试断言）、全部应用守护默认开、既有拦截/待办/提醒行为逐位不变。
- **SC-006**: `./gradlew :app:assembleDebug` 与 `:app:testDebugUnitTest` 全绿；Tracker 矩阵、v11→v12 迁移、DAO 聚合、守护列默认值测试齐备；README/AGENTS 口径同步。

## Assumptions

- 回弹层视觉沿用拦截覆盖层 token（品牌色、浅色、居中、56dp 按钮），与入口减速带同语言但无倒计时——「同一家人的两种语气」。
- 待办卡视图从 BlockingOverlay 提取为共享组件（`blocking/OverlayTodoCard`），两覆盖层同源渲染，不复制四态逻辑。
- 「继续 N 分钟」按钮文案的 N 取**弹层创建时刻**的配置值；选继续后装计时重新读配置。
- 会话时长含中途短暂离开（墙钟口径），已知高估；「净使用」精确统计留待未来（需要前台tick，成本高收益低）。
