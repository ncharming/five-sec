# Feature Specification: 拦截反馈三件套（成功态 / 抵制率 / 时段分布）

**Feature Branch**: `011-intercept-feedback`

**Created**: 2026-10-10

**Status**: Draft

**Input**: 用户认可的演进方向——现有产品的反馈强在「可比」（统计页周期聚合），弱在「即时」（决策瞬间）与「结果导向」（度量的是拦截次数这一过程指标）。本 spec 补三块：① 选择取消的瞬间给正反馈（成功态）；② 把「抵制率」提为统计主页一等指标（结果指标）；③ 拦截二级页新增 24 小时时段分布（自我洞察）。三件全部为只读侧增强，不新增表、不改 `interception_events` schema、不触碰离线红线。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 取消成功态：抵制瞬间的即时正反馈（Priority: P1)

用户在拦截页倒计时结束点了「取消」：覆盖层立刻切入成功态——「✓ 已抵制」+「今日第 N 次抵制」（N 含本次）+ 一次轻震动，停留约 0.8 秒后回桌面。选「打开」与被打断（INTERRUPTED）不出现成功态。

**Why this priority**: 行为设计的冲动重定向——把「我忍住了」从不可感知变成可感知的事件。这是三件套里唯一发生在决策瞬间的反馈，也是最便宜的多巴胺回路。

**Independent Test**: 今天已有 2 次取消 → 触发拦截 → 倒计时结束点「取消」→ 覆盖层出现「✓ 已抵制 · 今日第 3 次抵制」+ 短震 → 约 0.8 秒后回桌面；统计页「今日取消」变 3。

**Acceptance Scenarios**:

1. **Given** 倒计时结束（ChoiceUnlocked），**When** 点「取消」，**Then** 立即进入成功态：主文案「✓ 已抵制」、副行「今日第 N 次抵制」（N = 今日取消数含本次）、一次 60ms 震动、两按钮禁用置灰。
2. **Given** 成功态展示中（0.8 秒内），**When** 再点「打开/取消」，**Then** 无效——结局已锁定为 CANCELED，不重复计数。
3. **Given** 成功态展示中，**When** 无障碍服务被关/进程被拆（markInterrupted），**Then** 立即按 CANCELED 收尾（跳过剩余展示），**绝不**改记 INTERRUPTED——用户已完成锻炼并做出选择。
4. **Given** 0.8 秒展示结束，**When** 进入 Finished(CANCELED)，**Then** 服务照既有契约先 `GLOBAL_ACTION_HOME` 再延迟 250ms 撤覆盖层（顺序契约不变，撤层延迟不变）。
5. **Given** 任一时刻，**When** 事件落库，**Then** 记录与本功能前完全一致（outcome=CANCELED、exerciseCompleted=true）——成功态只是展示层反馈，不改事件语义。

### User Story 2 - 抵制率：结果指标一等公民（Priority: P1)

统计主页「今日拦截」卡在双 Hero（拦截次数 | 连续天数）下方新增抵制率行：「抵制率 75%」。抵制率 = 今日取消 / (今日取消 + 今日打开)；INTERRUPTED 不进分母（未做出选择不算一次「抵制机会」）；分母为 0（今天还没做出过选择）显示「—」。

**Why this priority**: 「拦截了多少次」是过程指标，「拦截后忍住了多少比例」才是产品要优化的结果指标。没有它，用户 10 次全打开和 10 次全取消在主页上看起来只差底部一行小字。

**Independent Test**: 今天 3 取消 1 打开 → 主页今日拦截卡抵制率 75%；只有 2 打开 0 取消 → 0%；只有打断无选择 → 「—」。

**Acceptance Scenarios**:

1. **Given** 今日 3 次取消、1 次打开，**When** 看统计主页今日拦截卡，**Then** 双 Hero 下方显示「抵制率 75%」（品牌绿加粗），原「取消 X · 打开 Y」小字行保留在其下。
2. **Given** 今日全部打开（0 取消），**Then** 抵制率 0%（0 是有效数据，照常渲染）。
3. **Given** 今日只有 INTERRUPTED 事件（分母 0），**Then** 抵制率显示「—」，不显示 0%（无选择 ≠ 0% 抵制）。
4. **Given** 今日无任何事件，**Then** 抵制率「—」，其余照常渲染 0（空态契约延续：零是有效数据）。

### User Story 3 - 拦截时段分布：几点最容易破防（Priority: P2)

应用拦截统计二级页（日/周/月/年档位）在周期筛选下方新增「时段分布」卡：24 根柱（0–23 时）展示所选周期内各小时的拦截次数，峰值柱高亮并标注「峰值 22 时 · 7 次」，右上角「共 N 次」。无数据照常渲染（全零柱 + 基线）。

**Why this priority**: 很多人的拦截高度集中在深夜——这个洞察本身就驱动行为改变（早点睡 / 深夜更警惕），也为将来分时段策略提供依据。P2 因为它是洞察型反馈，不直接改变行为回路。

**Independent Test**: 本周拦截 12 次其中 7 次在 22 点 → 拦截二级页切「周 · 本周」→ 时段分布卡 22 时柱最高且高亮，标题行「共 12 次」，下方「峰值 22 时 · 7 次」。

**Acceptance Scenarios**:

1. **Given** 所选周期内有多小时分布的事件，**When** 打开拦截二级页，**Then** 24 柱按本地时区分桶渲染，柱高与该小时拦截次数成正比，峰值柱品牌绿实色、其余 35% 透明度。
2. **Given** 周期切换（日/周/月/年或历史周期），**When** 选择变化，**Then** 分布随之重查重渲染（与其他周期查询同口径，半开区间）。
3. **Given** 所选周期无任何事件，**Then** 卡片照常渲染：全零柱（高度 0）+ 基线 + 「共 0 次」，不显示峰值行。
4. **Given** 多个峰值并列（同最大值），**Then** 取最靠前的时刻标注（indexOfFirst 语义），仅该柱高亮。

---

### Edge Cases

- **成功态跨零点**：23:59:59 点取消、展示跨过零点——计数与归零以「点取消时刻」的今日为准（provider 调用时求值），不回溯。
- **镜像与事件表的瞬时差**：今日抵制序号来自仓库进程内内存镜像（init 从事件表播种 + 每次取消 +1），事件本体在成功态展示结束后异步落库——镜像可能领先事件表最多一次；进程重启后播种自动对齐。统计页抵制率走事件表实时聚合，两者口径长期一致、瞬时可能差 1（展示 800ms 窗口内），属可接受偏差（已记录于 data-model.md）。
- **播种竞态**：仓库构造时后台播种完成前用户已取消——序号从内存值起算（可能小于真实值），仅影响展示数字、不丢事件；播种完成后取 max 对齐。
- **时钟回拨/时区切换**：镜像按日期字符串比对，回拨日保留现值（不归零不重复）；时段分布按查询时刻本地时区分桶，历史事件的桶归属随系统时区口径。
- **打断不进抵制率分母**：INTERRUPTED 是「未完成选择」，既不算抵制也不算放弃——分母与分子都只认 CANCELED/OPENED。
- **深色/浅色**：覆盖层恒浅色（既有契约），成功态沿用品牌绿 token；统计页跟随 App 主题。
- **今日拦截卡锚点**：双 Hero 结构不变，抵制率行是「计划内新增」（验证标准第 4 条的用户拍板例外路径，本 spec 即拍板记录）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 状态机 MUST 新增 `Resisted` 态：`ChoiceUnlocked --cancel--> Resisted(count) --800ms--> Finished(CANCELED)`；`Resisted` 是「已决定」态——此后 open()/cancel() MUST 无效，markInterrupted() MUST 立即转 `Finished(CANCELED)`（结局不翻案、锻炼完成语义不变）。
- **FR-002**: 成功态展示 MUST 满足：主文案「✓ 已抵制」、副行「今日第 N 次抵制」（N 含本次，N=1 亦显示）、60ms 单次震动（复用既有 VIBRATE 权限，失败静默）；MUST NOT 出现铃声（与 010 提醒的感官等级严格区分）。
- **FR-003**: 拦截时序契约 MUST 不变：成功态展示发生在 HOME 之前（覆盖层全程遮挡目标应用），Finished(CANCELED) 后服务照旧先 `GLOBAL_ACTION_HOME` 再延迟 250ms 撤层；撤层延迟常量 MUST NOT 改动。
- **FR-004**: 今日待办卡片 MUST 仍是覆盖层唯一缓冲内容（009 契约零触碰）——成功态只复用既有倒计时行并新增一行计数副行，不新增缓冲区块。
- **FR-005**: 今日抵制序号 MUST 由仓库内存镜像提供（init 从事件表按「今日 CANCELED 计数」播种；每次点取消同步 +1；日期字符串不等即归零起 1）；事件落库路径、字段、时机 MUST 与现状逐位一致。
- **FR-006**: 抵制率 MUST = 今日取消 / (今日取消 + 今日打开)，四舍五入取整百分比；分母 0 MUST 显示「—」；计算 MUST 是零 Android 依赖纯函数并配单测；INTERRUPTED MUST NOT 进分母。
- **FR-007**: 「今日拦截」卡 MUST 保留双 Hero（拦截次数 | 连续天数）与「取消 X · 打开 Y」小字行，抵制率行插在发丝线与小字行之间（品牌绿加粗）；整卡可点语义不变。
- **FR-008**: 时段分布 MUST 为 24 桶（0–23 时）本地时区聚合，数据源 = 周期内全部拦截事件（含 INTERRUPTED，与「拦截次数」总数同口径）；分桶 MUST 是显式 ZoneId 参数的纯函数并配单测；查询 MUST 是半开区间 [start, end) 响应式 Flow。
- **FR-009**: 时段分布卡 MUST 在无数据时照常渲染（全零 + 基线 + 「共 0 次」，无峰值行）；峰值标注 MUST 为「峰值 H 时 · M 次」且仅在 max>0 时出现。
- **FR-010**: 本功能 MUST NOT 改 DB schema（Room 恒 v11，现状版本——2026-10-04 wasExpired 列）、MUST NOT 对 `interception_events` 引入任何写操作（新增查询只读）、MUST NOT 引入网络/分析依赖或新 Gradle 依赖。

## Success Criteria *(mandatory)*

- **SC-001**: 点「取消」后 0.8 秒内可见成功态（✓ 已抵制 + 今日第 N 次抵制 + 短震），随后回桌面；统计页今日取消 +1；再次拦截再取消序号 +1；跨日归零。
- **SC-002**: 今日 3 取消 1 打开 → 主页抵制率 75%；全打开 → 0%；无选择 → 「—」；INTERRUPTED 不影响分母。
- **SC-003**: 拦截二级页任一档位/周期均有时段分布卡；峰值高亮正确；切周期即时重查；空周期渲染全零。
- **SC-004**: 覆盖层其余行为逐位不变：倒计时锁定、待办卡四态、打开路径、打断路径、O 规避（先 HOME 后撤层）。
- **SC-005**: `./gradlew :app:assembleDebug` 与 `:app:testDebugUnitTest` 全绿；新增纯逻辑（抵制率/分桶）与状态机（Resisted 迁移表）、DAO 区间查询、仓库镜像口径测试齐备；README/AGENTS 口径同步。

## Assumptions

- 0.8 秒展示时长是常量 `RESIST_DISPLAY_MS = 800L`（与 DEBOUNCE_MS 同量级的「体感一瞬」），不做成设置项。
- 震动为一次性 60ms `VibrationEffect.DEFAULT_AMPLITUDE`，不做波形（与提醒的闹钟式长震区分）。
- 时段分布柱状图为 Compose Canvas 手绘（24 根柱 + 基线 + 5 个轴标签 0时/6/12/18/23时），不引入图表库。
- 「抵制率」命名固定（不是「自控率」「成功率」）：主语是「抵制住了打开冲动」这个动作。
