# Quickstart: 拦截反馈三件套手测（specs/011）

真机 `adb install -r app/build/outputs/apk/debug/app-debug.apk` 覆盖升级后逐项过：

## 0. 升级零感知（回归锚点）

1. 老版本正常使用中 → 安装 011 构建（无迁移、无新表，直接覆盖；Room 版本维持 v11）。
2. 触发一次拦截：倒计时锁定、「请先思考 N 秒」、今日待办卡四态、点「打开」的抑制放行——逐位与升级前一致。
3. 待办页/设置页无任何新 UI。

## 1. 取消成功态（核心场景）

1. 打开抖音触发拦截 → 等倒计时结束 → 点「取消」。
   ✓ 覆盖层立刻变「✓ 已抵制」+ 副行「今日第 N 次抵制」（首次为 1）+ 手感一次短震；按钮变灰不可点。
   ✓ 约 0.8 秒后回桌面（不闪现抖音）。
2. 再触发两次拦截并取消 → ✓ 序号递增（第 2、3 次）。
3. 今天已取消 2 次后杀掉五秒进程（或关开无障碍服务）→ 再取消一次 → ✓ 序号接续正确（第 3 次，播种对齐）而非从 1 重来。
4. 跨零点验证（可选）：23:59 取消一次 → 00:01 再取消 → ✓ 新的一天序号从 1 起。
5. 统计页「今日取消」与成功态序号对得上（允许瞬时差 1：事件在 0.8s 展示后落库）。

## 2. 成功态的边界

1. 倒计时中点「取消」→ ✓ 无效（仍倒计时），不出现成功态。
2. 成功态展示的 0.8 秒内连点「打开/取消」→ ✓ 无反应、序号不变、结局仍是取消（回桌面）。
3. 成功态展示期间关掉无障碍服务 → ✓ 直接按取消收尾（回桌面），统计记 CANCELED 不记打断。
4. 选「打开」→ ✓ 无成功态（直接进应用，抑制窗口照旧）。

## 3. 抵制率（统计主页）

1. 今天 3 取消 1 打开 → 统计主页「今日拦截」卡：✓ 发丝线下出现「抵制率 75%」（品牌绿加粗），原「取消 3 · 打开 1」小字在其下；双 Hero 与整卡可点不变。
2. 今天全部打开 → ✓ 抵制率 0%。
3. 今天只有被打断（无选择）→ ✓ 抵制率「—」（不是 0%）。
4. 跨零点后重进统计页 → ✓ 按新一天重新计算。

## 4. 时段分布（拦截二级页）

1. 统计主页点「今日拦截」卡 → 二级页周期筛选下方：✓ 新增「时段分布」卡，24 柱、右上角「共 N 次」、下方 5 点轴标（0时/6/12/18/23时）。
2. 制造分布：白天取消/打开若干次、22 点前后再拦截几次 → 切「周 · 本周」→ ✓ 22 时柱最高且品牌绿高亮，其余柱浅色；下方「峰值 22 时 · M 次」。
3. 切「日/月/年」与历史周期 → ✓ 分布随周期重查重渲染。
4. 挑一个无事件的周期（如早年月份）→ ✓ 卡片照常渲染全零柱 + 基线 + 「共 0 次」，无峰值行。
5. 打断（INTERRUPTED）事件也计入柱高（与「拦截次数」总数同口径）。

## 自检口径（验证标准）

- `./gradlew :app:assembleDebug`、`./gradlew :app:testDebugUnitTest` 全绿（含 ResistRateTest / HourDistributionTest / BlockingViewModelTest 迁移表 / DAO 区间查询 / InterceptionRepositoryTest 镜像口径）。
- `interception_events` 无 DELETE、无 schema 变更（Room 恒 v11）；覆盖层待办卡四态与缓冲区契约零触碰。
- README「工作原理」「统计」段与 AGENTS 术语表已同步；tasks.md 全勾。
