# Feature Specification: 一次性待办与过期分类

**Feature Branch**: `007-oneoff-todos`

**Created**: 2026-10-12

**Status**: Draft

**Input**: 用户经 /grill-me 质询后拍板的口径——
1. 待办可能是暂时的：新增第四种规则「仅今天」，不需要重复，今天的完成即可；
2. 待办页要考虑今日待办未完成导致的过期：展示分「今日待办 / 过期待办」两区；不重复（一次性）的过期进过期分类；重复类过期不进过期分类（沿用「拖延只顺延」，错过就等下次轮到）；
3. 每条待办展示创建时间（yyyy-MM-dd 即可）；
4. 拦截覆盖层今日待办卡片统一截 12 字、左对齐。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一次性待办「仅今天」（Priority: P1)

用户有些事只属于今天：今天要寄一个快递、今天要给某人回电话。添加待办时重复规则选「仅今天」：当天它和别的待办一样——可勾选、计入覆盖层 D/T、出现在拦截卡片里；当天完成即万事大吉；当天没完成，跨日进入「过期待办」分类，不再出现在今日清单与拦截卡片里。

**Why this priority**: 用户第一诉求——待办不该被「每日重复」的模型绑架，临时事项占了真实待办的大头。

**Independent Test**: 添加「仅今天」待办 → 当天可见可勾、上拦截卡片；调整系统日期到次日 → 该条移入过期待办区、不可勾、不上拦截卡片。

**Acceptance Scenarios**:

1. **Given** 一条「仅今天」待办（今天创建、未完成），**When** 今天打开待办页，**Then** 出现在「今日待办」区、可勾选，计入拦截卡片 D/T 分母。
2. **Given** 同一条待办今天已勾选完成，**When** 明天打开待办页，**Then** 该条已自动清理（今日区与过期区都不出现）。
3. **Given** 同一条待办今天未完成，**When** 明天打开待办页，**Then** 该条出现在「过期待办 (n)」区，不可勾选、无启用开关。

---

### User Story 2 - 过期待办的处理（Priority: P1)

用户的过期待办是「失败的存量」：能看见哪天失败了几件事，也能给自己一条活路——把过期条目「改为今天」重新来过，或者删掉眼不见为净。不允许迟到补勾（自律工具里补勾等于自欺，用户拍板）。

**Why this priority**: 与 Story 1 一体两面；没有出口的失败清单只会让用户放弃使用。

**Independent Test**: 制造若干过期条目 → 逐条点 ⋯ 菜单验证「改为今天」（回到今日区且当天可勾）与「删除待办」；确认无任何勾选入口。

**Acceptance Scenarios**:

1. **Given** 过期区一条待办（有效期日 2026-10-10），**When** 点 ⋯ 菜单「改为今天」，**Then** 该条回到今日区、当天可勾选，副行创建时间不变。
2. **Given** 过期区一条待办，**When** 点 ⋯ 菜单「删除待办」并确认，**Then** 该条消失。
3. **Given** 过期区任意条目，**When** 查看行内交互，**Then** 无勾选框、无启用开关、无「迟到补勾」入口。

---

### User Story 3 - 创建时间可见（Priority: P2)

用户能看到每条待办是哪天建的：行内标题下副行纯 yyyy-MM-dd，过期区副行显示有效期日（哪天失败的）；升级前就存在的老条目没有真实创建日，显示「—」，不伪造。

**Why this priority**: 用户明确要求；过期归因（哪天的失败）也依赖这个展示位。

**Independent Test**: 新建待办看副行日期==今天；老条目（升级带入）显示「—」；过期条目副行==其有效期日。

**Acceptance Scenarios**:

1. **Given** 新建一条待办，**When** 查看列表行，**Then** 标题下副行显示今天的 yyyy-MM-dd。
2. **Given** 升级前已存在的待办，**When** 升级后查看，**Then** 副行显示「—」。
3. **Given** 过期区条目，**When** 查看副行，**Then** 显示其有效期日（而非创建日）。

---

### User Story 4 - 覆盖层卡片 12 字截断 + 左对齐（Priority: P2)

拦截覆盖层的今日待办卡片是 5 秒阅读场景：每条截前 12 字（超长加省略号，省略号不计入 12），卡片内标题与条目整体左对齐（更像一张清单）；卡片外的提示语/倒计时/按钮维持居中不动。

**Why this priority**: 5 秒内可读性的克制取舍，用户指定。

**Independent Test**: 建一条 30 字待办触发拦截 → 卡片里只显示前 12 字+…，标题与条目靠左。

**Acceptance Scenarios**:

1. **Given** 一条 20 字的今日待办，**When** 触发拦截，**Then** 卡片条目只显示前 12 字 + …。
2. **Given** 任意待办卡片，**When** 查看，**Then** 「今日待办 D/T」标题与条目文本均左对齐。

---

### Edge Cases

- 重复→仅今天转换：有效期日=修改当天（当天轮到）；仅今天→重复：有效期日清空。切换不触碰文本/完成状态/创建时间。
- 「改为今天」= 重写有效期日为今天，创建时间不动；之后再次跨日未完成会再次过期。
- 已完成的一次性跨日 → 惰性物理删除（无后台任务，列表/快照加载路径顺手清），不留在过期区（过期区只收失败）。
- 停用的一次性跨日 → 同样过期（有效期不看开关；过期区本就无开关无卡片曝光）。
- 时钟回拨导致有效期日 > 今天 → 不轮到也不算过期，暂归今日区灰显（防御分支，正常路径不可达）。
- 老数据升级：createdAt/dueDate 回填空串——老条目副行「—」；老条目全是重复类，空 dueDate 零影响。
- 惰性清理与 UI 双保险：VM 派生同时过滤「已完成且完成日≠今天」的一次性行，物理删除前 UI 也不露出僵尸行。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 重复规则 MUST 四选一：每天 / 按星期几 / 每 N 天 / 仅今天；规则编辑器 MUST 支持双向转换；新建默认「每天」不变。
- **FR-002**: 「仅今天」MUST 只在有效期日（dueDate）等于今天时轮到；有效期日在新建（=今天）、转为仅今天（=转换当天）、改为今天（=当天）时写入，转回重复类时清空；创建时间（createdAt）MUST 只在插入时写一次、永不改写。
- **FR-003**: 过期 MUST 定义为：仅今天 && 有效期日 < 今天 && 未完成；重复类 MUST NOT 进入过期分类。过期条目 MUST 不可勾选、MUST NOT 出现在拦截卡片，MUST 提供「改为今天」与「删除待办」操作，MUST NOT 提供迟到补勾。
- **FR-004**: 已完成的一次性待办在跨日后 MUST 被惰性物理删除（无定时任务/通知；加载路径顺手清）；删除 MUST 仅作用于 todos 表，MUST NOT 触碰 interception_events（红线）。
- **FR-005**: 待办页 MUST 分两区：「今日待办」（一切未过期条目，维持 id 升序、既有灰显/停用机制）与「过期待办 (n)」（按有效期日升序，最早失败在前）；无过期时第二区 MUST 不显示；20 条上限两区共享。
- **FR-006**: 每条待办行 MUST 在标题下展示副行日期：今日区=创建日（老条目显示「—」）、过期区=有效期日；详情弹窗同步展示。
- **FR-007**: 拦截覆盖层卡片条目 MUST 截前 12 字（超长加省略号，省略号不计入）；卡片内标题与条目 MUST 左对齐；卡片外元素对齐方式不变。
- **FR-008**: 升级迁移 MUST 零丢失：todos 新增 createdAt/dueDate 两列（TEXT NOT NULL DEFAULT ''），存量行回填空串；MUST 配套手建库迁移测试；MUST NOT 使用破坏性兜底。
- **FR-009**: 时间口径 MUST 沿用设备本地时区自然日 + TimeProvider 注入 + 惰性求值；MUST NOT 引入网络/通知/新权限/统计页改动。

## Success Criteria *(mandatory)*

- **SC-001**: 「仅今天」待办：当天在今日区可勾且计入 D/T；次日未完成进过期区（不可勾、不上卡片）；次日已完成则两区都不出现。
- **SC-002**: 过期区「改为今天」后条目回到今日区、当天可勾；「删除待办」后消失；过期区无任何勾选入口。
- **SC-003**: 新条目副行=今天；老条目副行=「—」；过期条目副行=有效期日。
- **SC-004**: 覆盖层卡片：20 字条目只显示 12 字+…；标题与条目左对齐。
- **SC-005**: `gradle :app:assembleDebug` 与 `:app:testDebugUnitTest` 全绿；迁移 6→7 手建库测试通过；既有测试零回归（受签名影响的用例同步更新）。

## Assumptions

- 「首页」指拦截覆盖层今日待办卡片（用户质询确认）；App 待办 Tab 列表维持单行省略。
- 一次性与重复类共享 20 条上限、≤200 字校验、详情弹窗等既有契约。
- 过期区不做批量清理/统计；完成历史不留存（v1 共识延续）。
