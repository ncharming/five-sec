# Feature Specification: 每日待办与拦截流程打通（待办模块 + 拦截页待办卡片 + 信息架构重构 + 提示语循环）

**Feature Branch**: `005-daily-todos`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description（经 grill 共识确认）: "在拦截被触发时，于拦截界面同时向用户提示今日的待办任务，把拦截流程与每日待办打通——不仅拦截用户下意识刷视频的动作，还借助拦截时机推动用户完成每天的任务。待办模块为从零新建：固定每日清单（标题 ≤30 字 + 创建顺序 + 启用开关 + 每日自动重置），上限 20 条，第一版只读展示于拦截覆盖层、勾选在应用内待办页完成；底部 Tab 重构为 [待办, 拦截, 提示语, 统计] 且默认落待办，原「五秒」页内容并入「拦截源」页顶部并更名「拦截」；拦截覆盖层删除"添加提示语"输入链路（全部关联代码），待办以紧凑卡片展示；提示语展示由随机改为循环（游标持久化），存量栈式提示改挂为池。"

**Builds on**: [001-app-intercept-exercise](../001-app-intercept-exercise/spec.md)（拦截链路）、[004-custom-hints](../004-custom-hints/spec.md)（提示语池）。本特性不改动拦截触发机制、5 秒状态机、目标清单上限与统计口径，不引入任何网络/通知/新权限。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 每日待办清单页（新建「待办」首页 Tab） (Priority: P1)

用户进入应用默认落在新的「待办」Tab。这里维护一份**固定每日清单**：每条待办只有标题文本（≤30 字，写入前 trim、空白拒绝、超长硬截断），可新增、重命名、删除（确认弹窗）、启用/停用；每个自然日可对启用条目**勾选完成/取消勾选**，跨入新的一天后所有条目自动回到"未完成"（无需任何手动重置）。清单上限 20 条，满员时名额提示前置可见、添加动作被兜底拦截。空状态不预置种子数据，以引导文案 + 添加入口呈现。

**Why this priority**: 待办是本次整合的数据主体，没有它拦截页无内容可展示；同时它自己就是用户每天打开 app 的第一落点。

**Independent Test**: 新建两条待办并勾掉一条 → 退出重进状态保留；把系统日期改为次日 → 已勾条目自动恢复未完成。

**Acceptance Scenarios**:

1. **Given** 待办页为空，**When** 页面展示，**Then** 显示空态引导文案与右上角"+"添加入口，不出现任何预置待办。
2. **Given** 用户点击"+"，**When** 输入"背 20 个单词"并确认，**Then** 列表即时出现该条（创建顺序排列）；输入空白时确认按钮不可用；输入超过 30 字时硬截断在第 30 字。
3. **Given** 列表已有"背 20 个单词"，**When** 点击该条复选框，**Then** 勾选态呈现（划线/对勾样式）；再次点击恢复未完成。
4. **Given** 已于今天勾选"背 20 个单词"，**When** 系统日期跨入次日后再打开待办页，**Then** 该条目显示为未完成（每日自动重置，无需任何清理动作）。
5. **Given** 用户通过条目"⋯"菜单选择删除，**When** 确认弹窗点击确定，**Then** 条目从列表消失。
6. **Given** 用户停用某条待办，**When** 查看列表，**Then** 该条呈弱化态且不可勾选；名额行计数含停用条目（按已建条数计）。
7. **Given** 已建 20 条待办，**When** 点击"+"，**Then** 出现名额已满提示弹窗，无法进入添加。

### User Story 2 - 拦截覆盖层"今日待办"紧凑卡片 (Priority: P1)

任一目标应用触发拦截时，覆盖层在提示语文本与倒计时数字之间展示一块**只读**紧凑卡片：

- 标题行：「今日待办 D/T」（D = 今日已完成的启用条数，T = 启用总条数，实时口径）；
- 条目行：未完成条目逐行列出（`○` 前缀），最多 3 条，超出折叠为「…还有 N 条」；
- 全部完成时：整块只显示「今日待办已全部完成 ✓」；
- 启用条目为 0（含从未建过待办）时：整块隐藏，布局回到现状。

卡片在覆盖层创建瞬间定格（快照），倒计时期间与解锁后展示一致，无任何点击行为；5 秒状态机与按钮锁定逻辑零改动。

**Why this priority**: 这是用户核心诉求——"拦截的瞬间顺便看见今天该干什么"。

**Independent Test**: 建两条待办（一条勾掉）→ 触发拦截 → 卡片显示「今日待办 1/2」并列出未完成条目；停用全部待办后再触发拦截 → 卡片消失。

**Acceptance Scenarios**:

1. **Given** 启用待办 2 条均未完成，**When** 拦截触发，**Then** 卡片标题「今日待办 0/2」，条目区逐行显示 `○ 待办一`、`○ 待办二`。
2. **Given** 用户在待办页勾掉其中一条后再次触发拦截，**Then** 标题「今日待办 1/2」，条目区只列未完成那条。
3. **Given** 启用待办 5 条均未完成，**When** 拦截触发，**Then** 条目区显示前 3 条 +「…还有 2 条」。
4. **Given** 启用待办全部完成，**When** 拦截触发，**Then** 卡片仅显示「今日待办已全部完成 ✓」。
5. **Given** 无任何启用待办，**When** 拦截触发，**Then** 覆盖层无待办区块，其余布局与现状一致。
6. **Given** 卡片展示期间覆盖层保持打开，**When** 期间（通过其他途径）待办发生变化，**Then** 卡片不变（创建时定格）。

### User Story 3 - 信息架构重构：四 Tab [待办, 拦截, 提示语, 统计] (Priority: P2)

底部导航重构为 **[待办, 拦截, 提示语, 统计]**，冷启动与引导完成后的默认落点为「待办」。原「五秒」首页的"拦截总开关 + 无障碍服务状态卡"整体并入原「拦截源」页**顶部**，该页 Tab 与页头更名为「拦截」，副标题沿用「给无意识的刷手机加一道减速带」；页内自上而下为：页头（含"+"添加应用按钮）→ 拦截总开关卡（含无障碍状态行）→ 名额行 → 应用卡片列表 → 名额满提示。提示语页与统计页不动。

**Why this priority**: 为 US1 腾出首页位并让配置（总开关/无障碍）与清单（拦截应用）在同一页完成，属结构性改造，依赖 US1 的待办页存在。

**Independent Test**: 打开 app 默认显示待办页；切到「拦截」Tab 可见总开关卡在上、应用清单在下，总开关与无障碍一键开启行为与原「五秒」页一致。

**Acceptance Scenarios**:

1. **Given** 冷启动（或引导完成后），**When** 首页呈现，**Then** 底部 Tab 顺序为 [待办, 拦截, 提示语, 统计]，当前落点「待办」。
2. **Given** 用户切到「拦截」Tab，**When** 页面展示，**Then** 页头标题「拦截」、副标题「给无意识的刷手机加一道减速带」；第一张卡为拦截总开关 + 无障碍状态行（行为与原「五秒」页完全一致）；下方为应用名额行与卡片列表。
3. **Given** 用户在合并页操作总开关、无障碍一键开启、应用增删/启停，**When** 操作完成，**Then** 行为与重构前一致（零回归）。
4. **Given** 原独立「五秒」Tab 已不存在，**When** 遍历四个 Tab，**Then** 不出现重复的总开关入口。

### User Story 4 - 提示语循环展示与栈式机制退役 (Priority: P2)

**移除**拦截覆盖层的"添加提示语"输入行及其全部关联代码（输入框/保存按钮/反馈文案、服务侧入栈接线、Repository 栈逻辑与测试、`STACK` 常量）。提示语管理页（「提示语」Tab）的查看/添加/删除能力**完全不动**。

拦截展示由**随机**改为**循环**：序列 = 内置提示语（资源数组顺序）+ 自定义池（添加顺序），每次拦截取下一条，到末尾回到开头；游标持久化，进程被杀重启后从上次位置**续接**；序列增删后游标对长度取模继续（不保证轮转严格不重不漏）。v4→v5 迁移把存量 `kind='stack'` 行改挂为 `kind='pool'`（用户文字零丢失，并入循环序列）。

**Why this priority**: 依赖 US2 对覆盖层的改造（同一布局区域腾挪），且池语义变更影响提示语页文案口径。

**Independent Test**: 连续触发拦截 9 次，提示语按 内置 1→7→池条目→内置 1 顺序循环；杀进程重启后续接而非归零；老版本升级后原"留一句话"出现在池中并可被轮到。

**Acceptance Scenarios**:

1. **Given** 提示语池为空，**When** 连续触发拦截，**Then** 依次展示内置 7 条并循环（不再随机）。
2. **Given** 池中已添加"早点睡觉"，**When** 内置 7 条轮完后继续拦截，**Then** 展示"早点睡觉"，再下一次回到内置第 1 条。
3. **Given** 循环进行到第 3 条，**When** 杀死进程后再次触发拦截，**Then** 从第 4 条继续（游标持久化）。
4. **Given** 覆盖层已弹出，**When** 检查覆盖层元素，**Then** 不存在提示语输入框/保存按钮（功能已移除）。
5. **Given** 旧版本数据库中存在栈式提示"别刷了，去写作业"，**When** 升级到本版本（v4→v5 迁移），**Then** 该文本进入池并参与循环轮转。
6. **Given** 提示语管理页，**When** 查看文案，**Then** 副标题/空态描述与"循环展示"口径一致；添加/删除行为不变。

### Edge Cases

- **跨日重置为惰性求值**：不依赖任何后台清理；"是否已完成"恒以 `最近完成日 == 今天` 判定，昨天勾的今天自然视为未完成。
- **时区口径**：日期边界按设备本地时区自然日（与统计页 `DateUtil` 同源）；CI（UTC）下测试显式传 `ZoneId`。
- **待办删除**：删除即消失，v1 不留存完成历史（无完成率统计）。
- **重复文本**：待办与提示语均允许重复，不去重。
- **序列为空**（理论不可达）：提示语循环对空序列有防御性兜底，不崩溃。
- **游标越界**（序列缩短后）：读时取模兜底，不抛异常。
- **覆盖层快照**：待办与提示语均在覆盖层创建瞬间定格，存续期间不变（与现有 `InterceptionController` 快照模式一致）。
- **30 字口径**：待办标题与提示语同一规范——trim 后非空白、按字符计数硬截断 30。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 待办条目 MUST 仅由标题文本构成（≤30 字、trim 后非空白），不支持时间/备注/子任务。
- **FR-002**: 完成状态 MUST 以"最近完成日 == 今天（设备本地时区）"判定，跨日自动回到未完成（惰性重置）。
- **FR-003**: 待办页 MUST 支持新增、重命名、删除（确认弹窗）、启用/停用、今日勾选/取消勾选。
- **FR-004**: 待办数量上限 MUST 为 20 条；满员时名额提示前置可见，添加动作 MUST 被拒绝并提示。
- **FR-005**: 覆盖层上的待办 MUST 只读；勾选仅发生在待办页。
- **FR-006**: 拦截覆盖层 MUST 在提示语文本与倒计时之间展示今日待办卡片：标题「今日待办 D/T」+ 未完成条目（`○` 前缀，最多 3 条，超出「…还有 N 条」）；全部完成显示「今日待办已全部完成 ✓」；启用条目为 0 MUST 整块隐藏。
- **FR-007**: 覆盖层待办快照 MUST 在覆盖层创建时主线程同步获取（内存快照，零 IO 阻塞），存续期间不变。
- **FR-008**: 底部导航 MUST 为 [待办, 拦截, 提示语, 统计]，默认落「待办」；原「五秒」页的总开关卡（含无障碍状态行）MUST 并入「拦截」页顶部，原独立「五秒」页 MUST 移除。
- **FR-009**: 拦截覆盖层的提示语输入链路（UI、回调、入栈逻辑、关联文案与测试）MUST 全部移除。
- **FR-010**: 提示语拦截展示 MUST 为循环：序列 = 内置（资源数组顺序）+ 自定义池（id 升序），每次拦截推进一条，末尾回环。
- **FR-011**: 循环游标 MUST 持久化，进程重启后续接；序列增删后 MUST 对当前长度取模继续。
- **FR-012**: 存量 `kind='stack'` 提示 MUST 经 v4→v5 迁移改挂为 `kind='pool'`（零丢失）；`interception_events` 与 `target_apps` 零触碰。
- **FR-013**: 拦截触发、5 秒状态机、按钮锁定、拦截记录、统计四卡、目标清单管理 MUST 零回归。
- **FR-014**: 待办 MUST NOT 引入通知、闹钟、网络或任何新权限；不进统计页、不影响连续天数语义。

### Key Entities *(include if feature involves data)*

- **待办（Todo，新增）**：每日固定清单条目——自增 id（创建顺序）、标题文本（≤30 字）、启用开关、最近完成日（"yyyy-MM-dd"，空串=从未完成）；完成判定 = 最近完成日等于今天。
- **今日待办（TodayTodo，新增值类型）**：覆盖层快照行——文本 + 今日是否已完成。
- **提示语（Hint，语义收敛）**：`kind` 只剩 `pool`（自定义池）；`stack` 随拦截页输入退役，存量行迁移并入池。
- **循环游标（hint cursor，新增）**：DataStore 整型，记录下一次应展示的序列下标；持久化键与既有设置同库。
- **拦截事件（现状，不变）**：待办与提示语变化不影响其记录字段。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 建 A/B 两条待办 → 拦截页显示「今日待办 0/2」+ 两条 `○` 条目；在待办页勾掉 A → 再次拦截显示「今日待办 1/2」且条目区仅剩 `○ B`（展示与勾选联动）。
- **SC-002**: 今日勾选后跨入次日（或调整系统日期），待办页与拦截页计数均回到未完成口径（每日重置生效）。
- **SC-003**: 停用条目不出现在覆盖层、不计入分母；全部停用/无待办时覆盖层无待办区块。
- **SC-004**: 第 21 条待办无法添加且出现名额提示；30 字截断与空白拒绝在待办与提示语两处口径一致。
- **SC-005**: 连续拦截的提示语严格按序列循环；杀进程重启后续接；v4 老库升级后栈式提示进入循环序列（迁移零丢失）。
- **SC-006**: 底部 Tab 顺序/默认页/合并拦截页布局符合 FR-008；总开关与无障碍一键开启行为与重构前一致。
- **SC-007**: 全部自动化测试通过：新增（todos 迁移、循环游标、每日重置、TodoRepository）+ 既有全绿零回归；`assembleDebug` 编译通过。

## Assumptions

- "每日"按设备本地时区自然日；不做时区穿越补偿。
- 待办完成历史 v1 不留存（仅记录最近完成日），不产生任何待办统计。
- 覆盖层待办卡片只读，无点击目标；用户想勾选需自行进入待办页（这正是"把用户拉回 app"的引导）。
- 提示语循环序列内置在前、池按添加顺序在后；游标只保证"轮着来"，不保证增删瞬间不重不漏（共识确认的取舍）。
- 游标持久化复用既有 DataStore（同库新键），不新增存储组件依赖。
- Tab 图标：待办用 Checklist（material-icons-extended 已在依赖内），其余沿用现状。

## Revision History *(交付后的行为修订，以代码为准)*

- **标题上限 30→200 字（用户反馈迭代）**：FR-001 / 关键实体 / 约束「30 字口径」/ SC-004 中"待办 30 字"的部分按新口径执行——待办页列表单行省略展示、点击条目弹只读全文弹窗、编辑弹窗多行输入（换行折叠为空格）；拦截卡片每条仅展示前 30 字（超长加省略号）；**提示语维持 30 字口径不变**。另：待办页顶部名额行（绿点进度段 + n/20）移除，容量语义由满员底部提示与添加兜底弹窗承载（FR-004 的上限 20 与拒绝行为不变）。
