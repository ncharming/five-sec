# Feature Specification: 任务完成统计（统计页双块重构）

**Feature Branch**: `008-todo-stats`

**Created**: 2026-09-23

**Status**: Draft

**Input**: 用户经 /grill-me 质询后拍板的口径——
1. 统计页加入待办任务完成情况：当天多少个任务、完成了多少个、过期几个；
2. 统计页分两块入口：应用拦截统计（今日拦截不变，历史数据做成二级页面）、任务完成统计（同应用拦截统计的结构）；
3. 历史数据来源：新增完成事件表 todo_completions（勾选落一行、取消即删，当天同条最多一行）；部署日起积累，不回填；
4. 历史页只展完成数（历史分母不可知），过期数只在今日卡出现；
5. 二级页用统计页内状态切换（保留底部 Tab 栏），共享日/周/月/年档位与周期选择。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 今日任务三数卡（Priority: P1)

用户打开统计页，在今日拦截卡的下方看到「任务 x / 完成 y / 过期 n」三列卡：x 是今天轮到且启用的待办数（与拦截覆盖层 D/T 分母完全同口径），y 是其中已勾选的，n 是过期待办区的条目数。三个数互不重叠、各说各话。

**Why this priority**: 用户第一诉求——待办功能（005/006/007）落地后，完成情况必须可见，否则清单只是清单。

**Independent Test**: 建若干条待办（每天/仅今天/停用各一），勾选一条，把一条仅今天改成昨天过期 → 统计页三数与待办页两区对得上。

**Acceptance Scenarios**:

1. **Given** 3 条今天轮到且启用的待办（1 条已勾选），**When** 打开统计页，**Then** 今日任务卡显示 任务 3 / 完成 1 / 过期 n。
2. **Given** 一条间隔规则待办今天完成（完成即进入灰显期），**When** 看今日任务卡，**Then** 该条不计入任务也不计入完成（与覆盖层 D/T 一致：轮到才计入）。
3. **Given** 一条停用的每天待办，**When** 看今日任务卡，**Then** 不计入任务（停用不进分母）。

---

### User Story 2 - 应用拦截统计二级页（Priority: P1)

统计主页保留今日拦截三列卡与连击卡不动；原「各应用历史数据」整块（日/周/月/年分段 + 周期 Chip + 按应用卡片）移入「应用拦截统计」二级页，从主页入口卡点入，返回箭头或系统返回键回主页。

**Why this priority**: 双块结构的地基——历史下沉二级页是用户指定的信息架构。

**Independent Test**: 主页点「应用拦截统计 ›」→ 档位/周期/应用卡与迁移前逐项一致；系统返回键回主页。

**Acceptance Scenarios**:

1. **Given** 统计主页，**When** 点「应用拦截统计」入口卡，**Then** 进入二级页，左上返回箭头可用，档位默认「日」。
2. **Given** 二级页，**When** 按系统返回手势/返回键，**Then** 回到统计主页（底部 Tab 栏全程保留）。

---

### User Story 3 - 任务完成统计二级页（Priority: P1)

「任务完成统计」二级页与拦截历史同构：日/周/月/年档位 + 周期 Chip；顶部周期总完成次数卡；下面按待办条目卡（每条「完成 N 次」，按完成次数降序）；周期内无完成时显示空态文案。二级页之间共享档位与周期选择（同一时间视角对比两块数据）。

**Why this priority**: 历史可回看是统计的核心价值；与拦截同构降低学习成本。

**Independent Test**: 勾选若干待办后进入二级页 → 周/月档位能查到对应次数；与拦截二级页切换时周期选择保持一致。

**Acceptance Scenarios**:

1. **Given** 本周勾选「背单词」3 次（3 天各一次），**When** 二级页选周/本周，**Then** 总完成 3 次，「背单词」条目卡显示完成 3 次。
2. **Given** 条目已被删除，**When** 查看其历史完成，**Then** 仍按删除当时的文本快照展示（历史不因删除失联）。
3. **Given** 周期内没有任何完成记录，**When** 打开二级页，**Then** 总次数 0 照常显示，列表区显示空态文案。

---

### User Story 4 - 勾选即留痕（Priority: P0，数据地基）

每次勾选待办当天写一行完成事件（含文本快照）；当天取消勾选即删该行；同一天勾-取消-再勾不会产生重复计数。升级部署前的历史完成无从追溯，统计从部署日起积累。

**Why this priority**: 没有事件表就没有历史统计——这是整个特性的数据地基。

**Independent Test**: 勾选→取消→再勾选同一待办 → 查询当日该条完成数恒为 1。

**Acceptance Scenarios**:

1. **Given** 待办 A 未勾选，**When** 勾选，**Then** todo_completions 新增一行（todoId + 当日 + 文本快照）。
2. **Given** 待办 A 今天已勾选，**When** 取消勾选，**Then** 该行被删除，当日完成数为 0。
3. **Given** 任意历史周期，**When** 查询应做数，**Then** 不存在（历史分母不可知：规则会改、条目会删会停用）——历史页只展完成数。

---

## Edge Cases

- 间隔规则完成当天不计入「任务/完成」两数（isDue=false，与 D/T 同口径），但完成事件照写（历史按天计数）。
- 一次性待办勾选当天计入、次日被惰性清理删除——完成事件行保留，历史仍可查（文本快照就是为此）。
- 重命名后勾选：事件快照写勾选当时的文本；同一周期内同一条目先旧名后新名完成，按 todoId 聚合展示一行（GROUP BY todoId，文本取任意行值）。
- 停用条目被勾选？不可发生——停用条目不可勾（既有契约），但若历史行存在仍照常聚合。
- 周期年份可选范围：拦截事件最早时间与完成事件最早日期二者取更早（年档位两个二级页都能覆盖各自历史）。
- 跨零点停留统计页：今日三卡（拦截/任务）沿用现状不自动刷新（VM 构造时锚定今天），切换 Tab/重进页面后刷新。
- 历史无回填：升级当日起积累，更早周期查询结果为 0——不是 bug，是没有数据（specs/002「0 值是有效数据」口径延续）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 新表 todo_completions MUST 只含 id/todoId/todoText/completedDate 四列，(todoId, completedDate) 唯一索引；MUST 仅由 TodoRepository.setCompleted 单点写入：勾选 upsert、取消删除。
- **FR-002**: 迁移 v7→v8 MUST 建表建索引、零破坏既有四表；MUST 配手建 v7 库迁移测试；MUST NOT 触碰 interception_events（红线）。
- **FR-003**: 今日任务卡三数口径 MUST 为：任务 = isEnabled && isDue(今天)（与覆盖层 D/T 同口径）；完成 = 其中 lastCompletedDate==今天；过期 = isExpired 条目数（含停用一次性，007 口径）。
- **FR-004**: 统计主页 MUST 保持今日拦截三列卡与连击卡原样，新增今日任务三列卡与两张单行入口卡；历史区块 MUST NOT 留在主页。
- **FR-005**: 两个二级页 MUST 与主页用页内状态切换实现（返回箭头 + BackHandler），底部 Tab 栏 MUST 保留；档位（日/周/月/年）与周期选择 MUST 两页共享。
- **FR-006**: 任务历史页 MUST 只展完成数维度：周期总完成次数 + 按条目完成次数（降序）；MUST NOT 展示历史完成率/应做数/过期数（不可知，不伪造）。
- **FR-007**: 条目卡 MUST 使用事件行的文本快照（todoText），删除的条目历史 MUST NOT 失联。
- **FR-008**: 年档位可选范围 MUST 取拦截最早事件与完成最早日期的更早者；查询区间沿用半开 [start, end) 的日期字符串比较（yyyy-MM-dd 字典序=时间序）。
- **FR-009**: 时间口径 MUST 沿用 TimeProvider 注入 + ZoneId 参数；统计页今日锚点沿用 VM 构造时捕获的现状；MUST NOT 引入网络/预聚合表/新权限。

## Success Criteria *(mandatory)*

- **SC-001**: 今日任务卡三数与待办页两区/覆盖层 D/T 对得上（同口径抽查通过）。
- **SC-002**: 勾-取消-再勾同一待办，当日完成数恒为 1；次日再勾为新一行。
- **SC-003**: 拦截二级页与迁移前的历史区块逐项一致（档位/Chip/应用卡/数据）。
- **SC-004**: 任务二级页周档位能查到本周勾选次数，删除条目按快照展示；空周期显示 0 + 空态文案。
- **SC-005**: `gradle :app:assembleDebug` 与 `:app:testDebugUnitTest` 全绿；迁移 7→8 手建库测试通过；既有测试零回归（受构造签名影响的用例同步更新）。

## Assumptions

- 「和现在的统计一样」= 档位/周期选择交互同构，不含按应用分组语义（任务按条目分组）。
- 今日三卡与连击卡留在统计主页（用户：「今日拦截不变」）；连击卡属拦截块不搬。
- 部署前的完成历史不回填、不估算（用户拍板接受）。
- 007 spec「完成历史不留存」的假设由本 spec 取代：todos 表本身仍只存最近完成日，历史留痕在独立的 todo_completions 事件表。
