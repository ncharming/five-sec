# Feature Specification: 添加应用搜索 + 应用级今日统计（品牌色展示）

**Feature Branch**: `002-app-search-perapp-stats`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "修改需求：1. 拦截应用清单添加时需要支持搜索功能。2. 统计模块：需要对细化应用级别进行统计，比如小红书今日拦截 xx、今日打开 xx，抖音今日拦截 xx。每个展示按照他们应用的 app 颜色来展示每个应用的统计数据。"

**Builds on**: [001-app-intercept-exercise](../001-app-intercept-exercise/spec.md)（五秒 / five-sec 基础特性）。本特性不改动 001 的拦截机制、3 个应用上限、权限流程与总体/历史统计，仅新增"添加应用搜索"与"应用级今日统计（品牌色）"两项增强。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 添加应用时通过搜索快速定位 (Priority: P1)

当用户在目标应用清单中"添加应用"时，系统列出设备上所有可添加的第三方应用供选择。由于设备上通常安装了大量应用，系统在列表顶部提供一个搜索框，用户输入应用名称（或包名）即可实时过滤候选列表，快速找到想添加的应用，而无需在长列表里肉眼翻找。

**Why this priority**: 目标清单最多 3 个应用，且默认只覆盖少数应用（抖音/小红书/B站）。要让用户把清单扩展到任何自己想拦截的应用，"添加"流程就必须能在数十甚至上百个已安装应用中高效定位目标。没有搜索，用户必须在长列表里肉眼滚动翻找，体验差且容易放弃配置——这直接削弱"自行配置被拦截应用"这一核心可配置价值，因此为最高优先级。

**Independent Test**: 在"添加应用"页面搜索框输入"微博"，验证候选列表立即过滤为匹配项；选择后微博进入目标清单。

**Acceptance Scenarios**:

1. **Given** 用户进入"添加应用"页面，**When** 页面加载完成，**Then** 显示设备上所有可添加的第三方应用列表，且列表顶部有一个搜索输入框。
2. **Given** 添加应用页面已显示全部应用，**When** 用户在搜索框输入"小红书"，**Then** 列表实时过滤，仅显示名称（或包名）包含"小红书"的应用，过滤在输入的同时发生。
3. **Given** 搜索结果已被过滤，**When** 用户清空搜索框，**Then** 列表恢复显示全部可添加应用。
4. **Given** 用户在搜索框输入包名片段（如 "com.weibo"），**When** 查看结果，**Then** 包含该片段的应用出现在结果中（支持按包名搜索，满足技术定位/重名场景）。
5. **Given** 用户输入一个不匹配任何应用的关键词，**When** 查看结果，**Then** 显示友好的空状态提示（如"未找到匹配的应用"），而非一片空白。
6. **Given** 候选列表中包含已在目标清单里的应用，**When** 用户浏览/搜索候选列表，**Then** 这些"已添加"应用被标识为不可重复添加（置灰或隐藏），避免重复加入。
7. **Given** 用户通过搜索找到一个未添加的应用，**When** 用户选择该应用，**Then** 该应用被加入目标清单；若清单已达 3 个上限（见 001 的 FR-007），**Then** 给出上限提示且不添加。

### User Story 2 - 查看每个应用的今日统计（应用品牌色展示）(Priority: P2)

统计页为每个目标应用单独展示一张统计卡片。卡片显示该应用"今日"的两个关键指标——**今日拦截次数**与**今日打开次数**。每张卡片以其对应应用的品牌色（取自该应用图标的代表色）作为视觉主题色，让用户一眼区分不同应用，直观感受自己当天对小红书、抖音等各个沉浸式应用的使用与拦截情况。

**Why this priority**: 001 已具备总体统计（拦截总数、取消率、完成锻炼次数）。本需求把统计细化到"按应用 + 按今天"两个维度，并用品牌色强化可识别性，帮助用户更精细地了解自己对不同应用的依赖程度、支撑更好的自我管理。它建立在已工作的统计基础之上，是价值增强而非核心阻塞，因此为 P2。

**Independent Test**: 今天对小红书触发 3 次拦截并打开 2 次、对抖音触发 1 次拦截并打开 0 次；打开统计页，验证：小红书卡片显示"今日拦截 3 / 今日打开 2"、抖音卡片显示"今日拦截 1 / 今日打开 0"，且两张卡片分别使用各自的品牌色。

**Acceptance Scenarios**:

1. **Given** 今天用户对小红书触发了 3 次拦截、其中 2 次选择"打开"，**When** 用户打开统计页，**Then** 小红书的统计卡片显示"今日拦截 3"与"今日打开 2"。
2. **Given** 今天用户对抖音触发了 1 次拦截、0 次打开，**When** 用户打开统计页，**Then** 抖音的统计卡片显示"今日拦截 1"与"今日打开 0"。
3. **Given** 统计页显示多个目标应用的卡片，**When** 用户浏览，**Then** 每张卡片以其对应应用的品牌色（取自应用图标代表色）作为主题色展示，不同应用的卡片视觉上可明确区分。
4. **Given** 今天未对某个目标应用发生任何拦截，**When** 用户打开统计页，**Then** 该应用卡片仍清晰呈现（如显示"今日拦截 0 / 今日打开 0"），不缺失。
5. **Given** 跨天场景（昨天与今天都有事件），**When** 用户在次日打开统计页，**Then** "今日"指标仅统计当天（设备本地时区、自然日 0 点起）的事件，不含昨日及更早数据。
6. **Given** 某应用图标无法提取出可用的代表色（极端情况），**When** 渲染其卡片，**Then** 系统使用一个合理的兜底主题色（如产品统一的健康绿）并保证文字可读，而非崩溃或空白。

### Edge Cases

**搜索相关**
- 设备上应用非常多（>200 个）时，搜索过滤仍需保持流畅（见 SC-001 的延迟目标）。
- 系统必备应用（电话、短信等）默认不出现在候选列表（与 001 假设一致）。
- 应用名称含 emoji / 特殊字符 / 多语言名称时的匹配行为，以及大小写、空格、全半角差异的容错。
- 设备上存在多个名称相近或包名前缀相同的应用时，搜索结果的区分与可读性。

**统计相关**
- 自然日切换（午夜 0 点）后"今日"指标归零的时机以设备本地时区为准。
- 应用图标为单色 / 近白色 / 近黑色，导致提取的品牌色与卡片文字对比度不足时的可读性兜底。
- "今日打开"的口径：明确为用户最终选择"打开"（outcome=OPENED）的事件；倒计时被打断（INTERRUPTED）不计入"打开"，但计入"今日拦截"总数。
- 应用被移出目标清单后，其历史今日数据在统计页的呈现策略（是否仍显示）。

## Requirements *(mandatory)*

### Functional Requirements

**添加应用搜索**

- **FR-001**: 系统 MUST 在"添加目标应用"流程中展示设备上所有可添加的第三方应用，并在列表顶部提供搜索输入框。
- **FR-002**: 搜索 MUST 支持按应用友好名称进行实时（边输入边过滤）匹配，且匹配不区分大小写。
- **FR-003**: 搜索 MUST 同时支持按应用包名进行匹配，以满足技术定位与重名场景。
- **FR-004**: 系统 MUST 在搜索无匹配结果时显示友好的空状态提示。
- **FR-005**: 系统 MUST 在候选列表中将"已在目标清单中"的应用标识为不可重复添加（置灰或隐藏），避免重复加入。
- **FR-006**: 搜索过滤 MUST 在设备安装大量应用（如 200+）时仍保持流畅（满足 SC-001 的延迟目标）。

**应用级今日统计（品牌色）**

- **FR-007**: 统计模块 MUST 为每个目标应用单独展示一张统计卡片。
- **FR-008**: 每张应用统计卡片 MUST 显示该应用"今日"的两个指标：今日拦截次数、今日打开次数。
- **FR-009**: 指标口径 MUST 明确为——"今日拦截"= 当日全部拦截事件数（含打开、取消、被打断）；"今日打开"= 当日用户选择"打开"（outcome=OPENED）的拦截事件数。
- **FR-010**: "今日" MUST 以设备本地时区的自然日（0 点起）为界；跨日自动归零，不混入历史数据。
- **FR-011**: 每张应用统计卡片 MUST 以该应用的品牌色作为主题色进行展示；品牌色 MUST 取自该应用图标的代表色。
- **FR-012**: 当应用品牌色无法提取、或与卡片文字对比度不足时，系统 MUST 使用兜底主题色并保证卡片文字可读（满足可访问性对比度）。

### Key Entities *(include if feature involves data)*

- **App Brand Color（应用品牌色）**: 取自某个目标应用启动器图标的代表色，用于该应用统计卡片的主题色。每个目标应用对应一个品牌色；无法从图标提取时使用兜底色。它是 TargetApp 的派生属性（运行时从图标提取/缓存，非用户手填）。
- **Today App Stats（今日应用统计）**: 按目标应用聚合的"当日"统计视图，每个目标应用一条，包含：应用标识（包名）、应用友好名称、应用品牌色、今日拦截次数（当日全部拦截事件数）、今日打开次数（当日 outcome=OPENED 的事件数）。由 InterceptionEvent 按"包名 + 当日时间窗"聚合得到，复用 001 既有拦截事件数据，不要求新增独立持久化实体（可缓存）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在已安装 200 个以上应用的设备上，用户在添加应用搜索框输入关键词后，候选列表在 0.5 秒内完成过滤刷新。
- **SC-002**: 用户通过搜索找到并添加一个不在默认清单的应用，平均操作时长不超过 15 秒。
- **SC-003**: 90% 的用户首次使用"添加应用"功能时，能不滚动浏览整个列表、仅凭搜索定位到目标应用。
- **SC-004**: 统计页每个目标应用卡片显示的"今日拦截"与"今日打开"次数，与当日实际发生的拦截/打开事件完全一致。
- **SC-005**: 每个应用的统计卡片使用彼此可明确区分的品牌色，用户能一眼识别哪张卡片对应哪个应用（可用性测试通过）。
- **SC-006**: 自然日切换后，"今日"指标自动且仅反映新一天的数据，无需用户手动刷新。
- **SC-007**: 应用统计卡片的文字与其品牌色背景之间保持足够对比度，在浅色与深色品牌色下均清晰可读（满足可访问性可读性）。

## Assumptions

- 本特性构建在已实现的 001 特性（五秒拦截 + 提肛引导 + 总体统计）之上；001 的拦截机制、3 个应用上限、权限引导流程保持不变。
- 添加应用搜索的对象是设备上已安装的第三方应用；系统必备应用（电话、短信等）默认不出现在候选列表（与 001 一致）。
- **应用品牌色取自该应用启动器图标的代表主色**（运行时从图标提取并缓存），而非内置固定色表——这是覆盖任意应用、零维护的默认方案。备选方案：为知名应用维护固定品牌色表、其余应用用图标提取兜底；本特性默认采用"纯图标提取"，如需固定色表可在 `/speckit-plan` 阶段调整。
- "今日"以设备本地时区、自然日 0 点为界。
- "今日打开"统计口径为用户最终选择"打开"（outcome=OPENED）的事件；倒计时被打断（INTERRUPTED）不计入"打开"，但计入"今日拦截"总数。
- 001 既有的总体/历史统计指标（取消率、完成锻炼次数、连续打卡 streak）不在本特性改动范围内，保持原样；本特性新增"按应用 + 今日"维度与品牌色展示。
- 候选列表中"已添加"应用的去重（置灰/隐藏）基于 001 既有目标清单数据。
- 本特性不引入账号、网络或后端；所有搜索、聚合计算与展示均在设备本地完成。
