# Spec: 抵制里程碑（specs/016）

## 背景

specs/011 的成功态反馈「今日第 N 次抵制」只有**当日**维度；连击（Streak）奖励「天天做」，但长期
总量的坚持没有任何正反馈——「这 200 天我总共抵制了 500 次」是最能强化「减速带在起作用」信念的
数字。本 spec 给抵制成功态追加**累计里程碑**，数据全在事件表，零新表。

## 需求

1. 抵制成功态（Resisted 0.8s 瞬态）在「今日第 N 次抵制」之下追加一行「累计抵制 M 次」——
   仅当 M 命中里程碑：**M = 50，或 M 为 100 的正整数倍**（50/100/200/300/…）。
2. M = 进程生命周期内累计 CANCELED 事件总数（含本次）：镜像在 init 从事件表播种、每次抵制 +1、
   不跨日归零（累计值与日期无关）。
3. 里程碑行样式与计数副行同层级（onSurfaceVariant 14sp），不抢「已抵制」主文案的视觉。
4. 不命中里程碑的抵制瞬态与现状完全一致（不多一行）。

## 方案

- **镜像扩展**：`InterceptionRepository` 的抵制镜像从「日期+当日计数」扩为「日期 + 当日计数 +
  累计计数」；init 播种一次 `COUNT(outcome=CANCELED)`（全表，无日期过滤——历史是资产），
  `nextResistedOrdinal` 同锁内对累计值 +1 并返回双值（data class `ResistOrdinals(today, total)`）。
- **纯逻辑**：`util/ResistMilestones.isMilestone(total: Long): Boolean`（==50 || %100==0），单测。
- **UI**：`BlockingViewModel.Resisted` 携带 `totalResisted`；`BlockingOverlay` 成功态按谓词追加行
  （文案进 strings.xml）；服务注入的 `resistCountProvider` 返回类型升级（默认值供测试）。
- **口径注意**：累计镜像与事件表同样存在「领先 ≤1」窗口（0.8s 展示期间未落库），进程重启播种
  自愈——与 011 当日镜像同一架构先例，可接受。

## 验收

- 造数：事件表已有 49 条 CANCELED → 下一次抵制成功态显示「今日第 1 次 + 累计抵制 50 次」；
- 第 51 次抵制（累计 51）不显示累计行；
- 累计 100/200 时各显示一次；当日跨零点后累计值不归零（当日序号归零照旧）。

## 红线沿用

不写新表；事件语义（exerciseCompleted/outcome）零改动——里程碑是纯展示层；反馈仍发生在
选择之后，不碰减速带与缓冲区契约（009/011）。
