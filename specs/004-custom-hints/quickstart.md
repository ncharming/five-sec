# Quickstart: 拦截页自定义提示语（栈式一次性提示 + 自定义提示语池）

**Date**: 2026-09-12 | **Spec**: [spec.md](spec.md)

端到端验证指南。自动化验证（CI / 本地）：

```bash
./gradlew :app:testDebugUnitTest        # 全部单测（含 HintDao/HintRepository/HintListViewModel/迁移）
./gradlew :app:assembleDebug            # 编译
```

## 前置

1. 真机/模拟器安装 debug 包（`./gradlew :app:installDebug`）。
2. 无障碍服务已开启；清单中已有目标应用（默认抖音/小红书/B站）。

## 场景验证

### 场景 A：拦截页输入 → 下次拦截优先展示（US1 / SC-001）

1. 打开目标应用触发拦截 → 覆盖层提示语下方出现输入框，占位提示"写句话留给下次拦截（30字内）"。
2. 倒计时期间直接输入"别刷了，去写作业"（验证：5 秒锁定不影响输入，FR-009）。
3. 点"保存" → 输入框清空、出现"已保存，下次拦截时展示"反馈（约 3 秒后消失）。
4. 等 5 秒解锁后点"取消"。
5. 再次打开目标应用 → 提示语位置显示"别刷了，去写作业"（栈顶优先，非随机内置）。
6. 解锁后取消；第三次打开 → 恢复随机内置提示（栈已消费空，FR-003/FR-004）。

### 场景 B：LIFO 顺序与多次保存（US1 / SC-001）

1. 连续两轮拦截分别保存 A（"第一次提示"）、B（"第二次提示"）。
2. 第三、四次拦截分别展示 B、A（最新优先）；第五次起恢复随机池。
3. 在第 4 步展示 A 时不做选择、直接按 Home（中断路径）→ 第 5 次拦截仍为随机池（A 已被消费，场景 5）。

### 场景 C：30 字截断与空白拒绝（US1 / FR-001 / FR-010）

1. 拦截页输入 40 个字符 → 输入停在第 30 个字符。
2. 只输入空格后点"保存" → 反馈"先写点什么再保存吧"，不入栈（下次拦截仍为随机池）。
3. 输入后不点保存、直接点"打开"/"取消" → 草稿丢弃（下次拦截不展示草稿）。

### 场景 D：自定义提示语池（US2 / SC-003）

1. 五秒 app 设置页 → "拦截应用清单"下方出现"自定义提示语"入口（位于"统计"之上，FR-006）。
2. 进入管理页 → 空态文案；点添加输入"早点睡觉"（同样 30 字截断）→ 列表即时出现该条。
3. 确保拦截栈为空（把已存的都消费掉），连续触发拦截 ≥20 次 → "早点睡觉"至少出现 1 次（与内置 7 条合并随机）。
4. 删除"早点睡觉"后再触发多次 → 不再出现该条（FR-007/FR-008）。

### 场景 E：持久化与升级（FR-005 / SC-002）

1. 保存 2 条栈提示后只消费 1 条 → `adb shell am force-stop com.fivesec.app` 杀进程。
2. 重新触发拦截 → 剩余 1 条栈提示仍按序展示（重启不丢）。
3. 覆盖升级（旧版本 v3 数据 + `adb install -r` 新包）→ 打开 app 正常，既有统计/清单零回归；新拦截后栈/池功能可用（v3→v4 迁移，SC-004 回归见 F）。

### 场景 F：回归（FR-011 / SC-004）

1. 拦截触发、5 秒倒计时、按钮锁定/解锁、打开/取消行为与改造前一致。
2. 统计页各档位数字、清单管理、总开关、无障碍状态均正常。
3. 既有测试全绿：`./gradlew :app:testDebugUnitTest`（含迁移测试 v3→v4）。

## 通过标准

- A~F 全部场景观察结果与预期一致；
- 单测/编译全绿（CI 触发于 push master 或手动 Run workflow）。
