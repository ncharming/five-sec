# Feature Specification: 拦截页自定义提示语（栈式一次性提示 + 自定义提示语池）

**Feature Branch**: `004-custom-hints`

**Created**: 2026-09-12

**Status**: Draft

**Input**: User description: "1. 在拦截页面增加一个自定义的文本描述，可以输入自己想要的提示内容，不超过30字（需要在输入框默认提示用户）。展现逻辑：用户输入后，会把用户输入保存到一个栈，下次打开拦截的应用时，先从此栈拿到文本信息往外提示（总是展示最新的信息），提示过后就可以出栈，当栈为空时，才把系统自定义的文本描述随机抽取一个展示出来。2. 进入五秒应用后，在拦截应用清单下面加一个自定义提示语入口：用户加入的自定义提示语默认成为系统自带的，用户打开拦截的应用后，会随机抽取一个展示。"

**Builds on**: [001-app-intercept-exercise](../001-app-intercept-exercise/spec.md)。本特性不改动拦截触发机制、5 秒状态机、目标清单与统计，仅扩展拦截覆盖层的提示语来源（内置随机 → 栈优先 + 随机池兜底）并在设置页新增提示语管理入口。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 拦截页输入自定义提示，下次拦截优先展示（栈式一次性提示） (Priority: P1)

拦截覆盖层（"是否打开 xxx？"页面）在提示语区域下方新增一个自定义提示输入框：用户可输入不超过 **30 字** 的提示内容（输入框内有默认占位提示说明用途与字数限制），点击"保存"后文本**入栈**并清空输入框、给出已保存反馈。下一次任一目标应用触发拦截时，提示语位置**优先展示栈顶（最新保存的）文本**，展示后该文本**出栈**（一次性消费，无论用户最终选打开/取消或页面被中断）；当栈为空时，才回落到现有逻辑——从系统提示语池中随机抽取一条展示。

**Why this priority**: 这是本需求的核心新增能力——用户在"被拦截的瞬间"给未来的自己写一句话，比静态内置提示更有行为干预力。栈式"最新优先 + 展示即消费"是用户明确指定的展现逻辑。

**Independent Test**: 在拦截页输入"别刷了，去写作业"并保存 → 再次打开目标应用触发拦截，验证提示语位置显示"别刷了，去写作业"而非内置随机提示；第三次触发时恢复为随机内置提示（栈已消费空）。

**Acceptance Scenarios**:

1. **Given** 拦截覆盖层弹出，**When** 页面展示完成，**Then** 提示语下方出现输入框，占位提示说明"可输入自定义提示，不超过 30 字"（未输入任何内容时的默认提示）。
2. **Given** 用户在输入框输入 12 个字，**When** 继续输入至第 31 个字，**Then** 输入被截断在第 30 个字，无法继续输入。
3. **Given** 用户已输入文本，**When** 点击"保存"，**Then** 文本入栈、输入框清空，并出现"已保存，下次拦截时展示"类反馈。
4. **Given** 栈中已有 2 条提示（先存 A、后存 B），**When** 下一次拦截触发，**Then** 展示 B（最新）；B 展示后出栈，再下一次拦截展示 A；A 出栈后再下一次拦截展示随机池提示。
5. **Given** 栈顶提示正在展示，**When** 用户选择"打开"或"取消"或页面被中断，**Then** 该提示均已被消费（出栈），不重复展示。
6. **Given** 用户输入了文本但未点"保存"，**When** 点击"打开"或"取消"结束拦截，**Then** 草稿不保存、不入栈。
7. **Given** 栈非空，**When** 拦截触发，**Then** 展示栈顶文本时**不**参与随机池抽取（栈优先级绝对高于随机池）。

---

### User Story 2 - 设置页"拦截应用清单"下方新增"自定义提示语"管理入口 (Priority: P2)

进入五秒应用设置页，在"拦截应用清单"菜单项下方新增"自定义提示语"入口。用户进入后可管理一个**自定义提示语列表**：查看全部已添加提示语、添加新提示语（同样不超过 30 字，输入框默认提示用户）、删除已有提示语。这里添加的提示语**并入系统提示语池**（与内置 7 条同等地位），在拦截栈为空时参与随机抽取展示。

**Why this priority**: 它扩充随机池的"弹药库"，价值依赖 US1 的展示链路（栈空才随机），但独立可用——仅实现 US2 时随机池扩充也立即生效于现状随机逻辑。

**Independent Test**: 在管理页添加"早点睡觉" → 清空拦截栈后多次触发拦截，验证"早点睡觉"会与内置提示一起随机出现（多次触发可观察到）。

**Acceptance Scenarios**:

1. **Given** 用户在设置页，**When** 页面展示，**Then** "拦截应用清单"下方出现"自定义提示语"入口（位于"拦截应用清单"与"统计"之间）。
2. **Given** 用户进入自定义提示语页，**When** 页面为空列表，**Then** 展示空态引导文案与添加入口。
3. **Given** 用户在添加框输入超过 30 字，**When** 继续输入，**Then** 截断在 30 字；输入为空或全空白时不可添加。
4. **Given** 用户添加提示语"多喝水"，**When** 保存成功，**Then** 列表即时显示该条目。
5. **Given** 列表中存在某条提示语，**When** 用户删除它，**Then** 列表即时移除，且不再参与随机抽取。
6. **Given** 自定义池中存在"多喝水"，**When** 拦截栈为空时触发拦截，**Then** 随机池 = 内置 7 条 + 全部自定义条目，"多喝水"有概率被抽中展示。

---

### Edge Cases

- **空白输入**：拦截页保存与管理页添加对空串/全空白输入一律忽略（不保存、给出无效果反馈或按钮禁用）。
- **30 字口径**：以字符计数（中文 1 字 = 1 字符），超限硬截断。
- **输入未保存即结束拦截**：草稿丢弃，不写入栈（避免误存半截文本）。
- **进程被杀/重启**：栈与自定义池均已持久化，重启后恢复；栈顶未被消费的提示仍保留。
- **中断（INTERRUPTED）也消费栈顶**：展示即出栈，与用户最终选择无关（见 US1 场景 5）。
- **并发拦截**：覆盖层已显示期间忽略后续事件（现状不变），不存在同一栈顶被两次消费的窗口。
- **重复文本**：允许相同文本重复入栈/入池，不去重。
- **栈深度**：不设上限，由用户自行管理（单条 ≤30 字，存储量可控）。
- **自定义池为空**：随机池 = 内置 7 条，与现状完全一致（零回归）。
- **随机分布**：栈空时在"内置 + 自定义"合并池上均匀随机抽取。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 拦截覆盖层 MUST 在提示语下方提供自定义提示输入框：占位提示说明用途与 30 字上限，输入硬截断 30 字。
- **FR-002**: 输入 MUST 经显式"保存"动作入栈；保存成功后输入框清空并给出已保存反馈；未保存的草稿 MUST NOT 入栈。
- **FR-003**: 拦截触发时 MUST 优先展示栈顶（最新）提示，展示即出栈（一次性消费），消费与拦截最终结果（打开/取消/中断）无关。
- **FR-004**: 栈为空时 MUST 从"内置 + 自定义"合并池中随机均匀抽取一条展示。
- **FR-005**: 栈与自定义池 MUST 持久化存储，应用/进程重启后不丢失。
- **FR-006**: 设置页 MUST 在"拦截应用清单"下方（"统计"上方）提供"自定义提示语"入口。
- **FR-007**: 自定义提示语页 MUST 支持查看列表、添加（≤30 字、非空白）、删除。
- **FR-008**: 自定义提示语 MUST 与内置提示语合并参与随机抽取，地位同等（US1 栈为空时生效）。
- **FR-009**: 输入框交互 MUST NOT 影响既有 5 秒状态机：倒计时期间输入框可用，"打开/取消"仍按原逻辑锁定/解锁。
- **FR-010**: 空白输入（空串或仅空白字符）MUST NOT 入栈/入池。
- **FR-011**: 既有行为 MUST 零回归：拦截触发、5 秒倒计时、按钮锁定、拦截记录与统计、目标清单管理均不变。
- **FR-012**: 提示语展示 MUST 在覆盖层创建时同步确定（不阻塞、不闪变），与现有 InterceptionController 快照模式一致。

### Key Entities *(include if feature involves data)*

- **提示语栈（hint stack，新增）**：用户在拦截页保存的一次性提示，LIFO；栈顶 = 最新保存；展示即消费删除。持久化存储。
- **自定义提示语池（custom hint pool，新增）**：用户在管理页维护的持久提示语列表；与内置提示语合并为随机池。
- **内置提示语（builtin hints，现状）**：`blocking_exercise_hints` 资源数组（7 条），只读、不可被用户修改删除。
- **拦截事件（现状，不变）**：提示语来源变化不影响其记录字段。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 保存 2 条提示（A 先 B 后）后连续触发 3 次拦截，三次展示分别为 B、A、随机池提示（LIFO 顺序 + 栈空回落）。
- **SC-002**: 保存提示后杀死应用进程重启，未消费的栈内提示仍按序展示（持久化有效）。
- **SC-003**: 自定义池添加 1 条后，栈空时触发拦截 ≥20 次，该条目出现次数 > 0 且其余展示均来自合并池（并入生效、无丢失）。
- **SC-004**: 既有全部自动化测试通过（零回归），新增栈/池逻辑有单元测试覆盖（含 LIFO 顺序、栈空回落、空白拒绝、30 字截断）。

## Assumptions

- "拦截应用清单下面"= 设置页菜单项"拦截应用清单"下方（"统计"之上插入），非清单页列表内部。
- 拦截页输入框在 5 秒倒计时期间即可输入（锁定的仅是"打开/取消"按钮）；倒计时与输入互不干扰。
- "提示过后就可以出栈"解释为**展示即消费**：覆盖层创建并展示该文本的瞬间出栈，与用户后续选择无关。
- 输入长度按字符计（中文 1 字符），硬截断，不做省略号等软提示。
- 允许重复文本；栈深度不设上限。
- 栈与池的存储沿用本机本地存储（与现有隐私承诺一致），不联网、不上传。
- 随机抽取不避免重复（连续两次拦截可能抽中同一条，与现状内置随机行为一致）。
