# Quickstart: 单次待办可选具体日期手测（specs/020）

真机 `adb install -r app/build/outputs/apk/debug/app-debug.apk` 后按序验证（覆盖安装可同时验证
存量单次零迁移：老「仅今天」条目照常当天轮到）。

## 1. 新建未来日单次

1. 待办页 → ＋ 新建 → 内容随意 → 规则段切「单次」→ 提醒区照 013 预填 20:00/21:00/22:00。
2. 单次段出现「生效日期」chip（默认今天）→ 点开日历：**过去日期不可选**（灰）、未来任意可选 →
   选两周后的日子 → 确认，chip 显示该日。
3. 保存 → 今日卡出现分组「**单次/2026-11-23**」（样式同「每 3 天」，单次段内）；行**灰显禁勾**，
   副行「今天不用做 · 提醒 20:00、21:00、22:00」。
4. 触发一次拦截 → 覆盖层卡片**不含**该条（不轮到不上卡，D/T 分母不计）。

## 2. 日期分组与排序

1. 再建一条单次选更近的日期（如明天）→ 今日卡出现两个单次组，**近日期在前**：
   「单次/明天」组在「单次/两周后」组上方；今天的单次组名同样带今天日期。
2. 同日再建一条 → 合入同组、组内按创建顺序。
3. 规则四段顺序不破：每天组 → 每周组 → 每N天组 → 单次组（们）。

## 3. 到期流转与提醒

1. （可把日期选「明天」缩短验证）到期日当天：该条离开灰显、可勾、进覆盖层卡片。
2. 到 20:00（未完成）→ 类闹钟提醒照 010/013 触发（全屏页 + 通知 + 铃震）；勾掉完成后 21:00/22:00
   不再响。
3. 跨过到期日仍未完成 → 进「过期待办 (n)」，副行=有效期日，⋯ 菜单「改为今天 / 删除」（无「修改」，
   单次过期口径不变）。
4. 建立时点到生效日之间：任何 20:00/21:00/22:00 **不响**（已过时刻绝不补响 + 只排在生效日）。

## 4. 编辑改期

1. 今日区单次条目 → ⋯「修改」→ 单次段「生效日期」chip 回显原日期 → 改选新日期 → 保存 →
   分组随迁到新日期组，文本/提醒/完成态不动。
2. 只改日期不动其他 → 保存后立即生效（定向 UPDATE，无需重开弹窗确认）。
3. 单次切回「每天」→ dueDate 清空、分组回「每天」；再切回「单次」→ 日期保留此前所选
   （与周几 chips 同口径），提醒时刻按 013 联动。

## 5. 弹窗滚动与全周日历（2026-11-13 修复）

> 根因：FiveSecDialog 外壳内容区不可滚、不限高——长表单（编辑弹窗）与 DatePicker 日历在
> 小屏机上超出屏高被窗口硬裁，日历底部的「未来周六/日」整行被裁到屏外点不到，观感即
> 「只能选周一到周五」。修复后为标准弹窗窗口结构：标题/按钮固定 + 独立垂直滚动内容区
> （屏高 85% 封顶）。日历可选域判定从未限定工作日（OnceDueDateSelectionTest 逐星期几断言锚定）。

1. 新建待办弹窗：内容整体超出弹窗封顶高度时，**在弹窗内部上下滑动**可看到全部区段
   （模板/内容/重复规则/提醒），标题与保存/取消按钮**始终可见不被顶出屏**；短弹窗
   （删除确认等）观感与既往一致（不出现多余滚动）。
2. 「单次 → 生效日期」打开日历：日历完整可见（必要时在弹窗内滑动查看）；
   **周六、周日与工作日同样可点**——选一个未来的周六或周日 → 确认 → chip 显示该日、
   保存后分组名「单次/该日期」。
3. 过去日期（今天之前，不分周几）仍为灰不可选：那是唯一被排除的日期段
   （过去日=建完即过期且提醒永不响）。

## 6. 存量回归（007/013 行为不回退）

1. 覆盖安装后，升级前的老单次（dueDate=当天创建）照常当天轮到、当天完成跨日清理。
2. 「改为今天」仍重写 dueDate 为当天（过期单次的活路不受影响）。
3. 切单次默认三时刻预填/离开还原（013）在带日期形态下照常。
