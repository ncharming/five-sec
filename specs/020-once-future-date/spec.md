# Spec: 单次待办可选具体日期（specs/020）

## 背景

「单次」待办（specs/007）原是「仅今天」：新建/切规则时 `dueDate` 由仓库硬编码为**保存当天**——
用户没法说「这件事 11 月 23 日再提醒我」。实际诉求：今天（如 11.9）记下一条两周后（11.23）要办的
事，希望它**只在 11.23 那天轮到、提醒、可勾**，并在待办页按日子归类展示。

数据层其实早已支持未来日期（007 的防御分支「时钟回拨导致有效期日 > 今天 → 不轮到也不算过期，
暂归今日区灰显」即此形态）：`isDue`/过期判定/僵尸清理/提醒排程全部按 `dueDate` 日期比较，零逻辑
改动。本 spec 只补**入口**（编辑弹窗选日期）与**归类展示**（分组键扩到有效期日）。

## 需求（用户原始口径）

新建/修改待办时，重复规则选「单次」可以设置具体某天：如 11.9 设置了 11.23 提醒的待办，
应分类显示到「**单次/2026-11-23**」。

## 方案

- **规则携带日期（零迁移）**：`TodoRule` 增第四列 `dueDate`（默认空串，仅单次有语义）——
  随 data class 相等参与「规则没变不发定向 UPDATE」判定，只改日期也正确触发。仓库
  `add`/`setRecurrence`：单次且携带合法 `yyyy-MM-dd` → 原样落库；空/非法 → 回落保存当天
  （007「仅今天」缺省，once 行 dueDate 空串会是永不轮到也永不过期的幽灵行，回落兜死）；
  转回重复类清空（不变式不变）。非法格式拒绝（表单 DatePicker 产出恒合法，仓库兜脏调用方）；
  **过去日刻意不拒**——那是合法状态（落库即过期、可「改为今天」），且拒绝会让跨零点保存静默失败
  （VM 对写失败静默忽略）。
- **编辑弹窗**：单次段新增「生效日期」chip，点开 `DatePicker`（FiveSecDialog 外壳，与 TimePicker
  同构；纯日历态不提供文本输入）。可选域 = 今天起（过去日无提醒意义：落库即过期且永不响铃）；
  默认今天、编辑回显原有效期日；确认选中不早于今天（编辑回显的历史日期不重选就被禁用按钮拦下）。
  日期与周几 chips 同口径：切走再切回保留所选。
- **分组展示**：`TodoRuleGroups` 分组键 = 规则**原值四列**（单次含 dueDate，重复类归一为空——
  脏值不拆重复类组）；单次组名「单次/2026-11-23」（`todos_group_once`，空 dueDate 脏形态退裸
  「单次」）；组序在四段内按有效期日**升序**（今天在前、未来渐远——近的活先看见）。
  > **2026-11-16 用户修订（现行口径）**：有效期日=今天的单次组**置顶卡首**（提到每天组之前）——
  > 「今天不做就没了」的绝对死线优先于节奏条目，与覆盖层卡片 `overlayPriority`「单次最前」同一
  > 紧急度口径；未来的单次是计划不是死线，仍按本条日期升序留在单次段。实现：`groupByRule` 增
  > `today` 参数（与灰显/分区派发同源的 VM 今日口径），置顶判定为字符串等值比较。
  >
  > **2026-11-16 二次修订（现行口径，泛化置顶）**：置顶扩到**一切当天轮到的组**——每N天（今天
  > 复活）、每周几（今天选中）同样置顶，每天恒轮到不参与（用户口径「除了每天之外」）；置顶档内
  > 按覆盖层 `overlayPriority` 紧急度序（单次→每N天→每周），今日卡置顶头部与拦截卡片前 3 条同序。
  > 置顶键改为**组内任一行 `TodoRow.dueToday`**（VM 与灰显「今天不用做」同一次求值：完成间隔
  > 条目即顺延 N 天、组自动退出置顶，跨零点随 ON_RESUME 重算联动）——`groupByRule` 不再需要
  > `today` 参数，间隔组锚点逐行不同故取「任一行轮到」整组置顶；未知脏类型不升位（脏值不错位
  > 兜底）。
- **提醒（复用 010/013，零新增链路）**：单次的提醒时刻本就排在 `dueDate` 当天——设了未来日的
  单次，默认 20:00/21:00/22:00（013 预填）在**生效日**各响一次；「已过时刻绝不补响」自动涵盖
  建立时点（建完到生效日之间不响）。
- **流转（复用 007，零新增链路）**：未到生效日 → 今日区灰显「今天不用做」（不轮到、不进过期区、
  不上覆盖层卡片）；生效日当天 → 轮到可勾、上卡片；跨过生效日未完成 → 过期区（副行=有效期日，
  可「改为今天」/删除）。已完成跨日清理（`lastCompletedDate ≥ dueDate` 且 ≠ 今天）对未来日同样成立。

## 验收

- 11.9 新建单次、生效日期选 11.23、提醒留默认三时刻 → 保存后今日卡分组显示「单次/2026-11-23」，
  行灰显禁勾、副行「今天不用做 · 提醒 20:00、21:00、22:00」；
- 11.10–11.22 每天查看：该条仍在「单次/2026-11-23」组灰显，**不响**任何提醒；
- 11.23：该条当天轮到可勾、进覆盖层卡片；20:00/21:00/22:00 到点响（未完成时）；
- 11.24（未完成）：进过期待办区，副行 2026-11-23，⋯ 菜单「改为今天/删除」；
- 编辑既有单次改日期（11.23 → 11.30）→ 分组随迁到「单次/2026-11-30」，其余列不动；
- 单次不同日期各自成组、组序按日期升序；今天的单次组名同样带日期（组名自描述，读侧=编辑侧词汇表）。
  > **2026-11-16 修订**：今天的单次组升为**卡首置顶**（见方案修订注），其余单次组照旧按日期升序。
  > **同日二次修订**：置顶泛化到一切当天轮到的组（每N天今天复活/每周几今天选中；每天除外），
  > 档内与拦截卡片紧急度同序——详见方案二次修订注。

## 红线沿用

零 schema 变更（dueDate 列 007 已有）；`interception_events` 只增不删不动；提醒不写事件表不进统计
（010）；纯离线无新增权限；纯逻辑（分组/日期归一）零 Android import 可单测。
