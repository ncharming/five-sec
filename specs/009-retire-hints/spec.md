# Feature Specification: 提示语功能退役（待办成为拦截页唯一缓冲内容）

**Feature Branch**: `009-retire-hints`

**Created**: 2026-09-24

**Status**: Draft

**Input**: User description: "提示功能与待办功能本质上服务于同一个目标（打断无意识刷视频、引导用户做有意义的事），因此功能上是重复的；待办既能记录用户的待办，也能减少刷视频软件的时间，价值更大。确认方案A：直接移除提示语功能——待办成为拦截缓冲层的唯一内容，空态由待办引导补位，不做『提示语→待办』转化。"

**Builds on**: [004-custom-hints](../004-custom-hints/spec.md)（引入自定义提示语）、[005-daily-todos](../005-daily-todos/spec.md)（提示语改循环轮换 + 引入今日待办卡片与信息架构）。本特性不改动拦截触发机制、5 秒状态机、统计与待办功能本身，仅退役提示语这条内容链路，并把它的空态职责交还待办卡片。

## 背景与决策

拦截页当前并行展示两套缓冲内容：一条**提示语**（内置 7 条 + 自定义池循环轮换，specs/004 引入、005 改循环）和一张**今日待办卡片**。两者岗位完全重叠——都在回答"这 5 秒该想点什么、去做点什么"。对比之下待办在每一维都占优：个人化承诺 vs 泛化文案、可勾选行动 vs 只读文案、有完成统计闭环（specs/008）vs 零反馈。提示语的原初价值（微行动"提肛"）早已被 5 秒锁定倒计时本身吸收，其个人化形态（004 栈式一次性提示）也已在 005 退役。

**已拍板（2026-09-24）**：整体移除提示语功能（方案A），不采用"降级兜底"（B1）或"转待办后退役"（B2）。理由：5 秒注意力是稀缺资源，应全部让给待办；空态是设计问题而非功能缺失，由待办空态引导补位比通用文案更好地服务核心循环。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 拦截页移除提示语，待办卡成为唯一缓冲内容 (Priority: P1)

用户打开目标应用触发拦截时，覆盖层不再出现提示语文本行：页面自上而下为标题、今日待办卡片、倒计时行（"请先思考 N 秒"→"✓ 请选择"）、打开/取消按钮。内置提示语与自定义提示语两个来源全部停用，无论用户曾配置多少条自定义提示语、无论拦截多少次，都不再有任何轮换文本出现。

**Why this priority**: 这是本特性的核心——把缓冲内容层收敛为单一主角（待办），直接兑现"待办为唯一提醒位"的产品定位；其余故事都是它的收尾与补位。

**Independent Test**: 在已添加若干自定义提示语的设备上触发拦截 → 页面只有标题/待办卡/倒计时/按钮，连续多次触发均无提示语文本出现。

**Acceptance Scenarios**:

1. **Given** 今日有待办未完成，**When** 拦截触发，**Then** 待办卡显示"今日待办 D/T"+ 未完成条目（现状规则不变），页面无任何提示语文本。
2. **Given** 今日待办全部完成，**When** 拦截触发，**Then** 待办区显示"今日待办已全部完成 ✓"（现状不变），页面无任何提示语文本。
3. **Given** 用户此前添加了自定义提示语并开启内置提示语，**When** 连续多次触发拦截，**Then** 没有任何一次出现轮换提示语。

---

### User Story 2 - 无待办时的空态引导：待办卡不再隐藏 (Priority: P1)

现状下"轮到且启用"的待办数为 0 时待办卡整块隐藏，缓冲层只剩倒计时——这正是提示语此前填充的位置。本特性把隐藏改为空态展示，且区分两种空态：用户**没有任何启用条目**时显示引导添加的文案（如"还没有今日待办，打开五秒添加"）；用户**有启用条目但今天都不轮到**时显示告知文案（如"今天没有轮到的待办"）。空态卡与普通待办卡同样只读，不提供输入或跳转。

**Why this priority**: 空态引导是移除提示语的安全网——它把"提示语兜底空态"的职责交还待办系统，并把空窗变成待办功能的拉新位；与 US1 同为 P1，缺它则 US1 在无待办用户处体验倒退。

**Independent Test**: 清空/停用全部待办后触发拦截 → 待办区显示引导文案而非消失；新建一条"仅周五"的待办后在非周五触发拦截 → 显示"今天没有轮到的待办"。

**Acceptance Scenarios**:

1. **Given** 没有任何启用的待办条目，**When** 拦截触发，**Then** 待办区可见空态引导文案（引导去应用内添加），倒计时与按钮行为不变。
2. **Given** 存在启用条目但今天没有任何条目轮到（如全部为"仅周五"而今天非周五），**When** 拦截触发，**Then** 待办区显示"今天没有轮到的待办"类告知文案，而非引导添加。
3. **Given** 空态展示中，**When** 用户在待办页添加今日轮到的待办后再次触发拦截，**Then** 恢复"今日待办 D/T"正常卡片。

---

### User Story 3 - 「提示语」Tab 与管理页整体退役 (Priority: P2)

底部导航从 4 Tab（待办 / 提示语 / 统计 / 设置）变为 3 Tab（待办 / 统计 / 设置），提示语管理页（自定义池增删、内置区开关）从任何入口都不可达；应用内不再出现任何提示语相关的界面与文案。

**Why this priority**: 内容层收敛后的配套信息架构收尾；独立于拦截页改动的用户可感知面。

**Independent Test**: 启动应用 → 底部导航仅 待办 / 统计 / 设置 三项；全应用遍历无提示语管理入口或相关文案。

**Acceptance Scenarios**:

1. **Given** 升级到本特性版本后启动应用，**When** 查看底部导航，**Then** 仅有 待办 / 统计 / 设置 三个 Tab，默认仍落待办。
2. **Given** 任意页面与入口，**When** 遍历应用，**Then** 不存在提示语列表、添加、删除、内置开关的任何界面或文案。

---

### User Story 4 - 存量数据零破坏 (Priority: P2)

用户已保存的自定义提示语数据不做删除：提示语数据表整体只读保留（不删表、不清空、不做破坏性迁移），循环游标与内置开关的持久化值停止读写后允许残留。待办、拦截事件、完成事件等其余数据零丢失。

**Why this priority**: 守住"历史数据是产品价值"的项目红线与纯离线产品对用户数据的尊重；对用户不可见，但决定升级路径是否安全。

**Independent Test**: 携带自定义提示语与待办数据的旧版本覆盖升级 → 待办/统计内容原样保留；用调试手段检查本地数据库，提示语表数据仍在。

**Acceptance Scenarios**:

1. **Given** 旧版本有 3 条自定义提示语与 5 条待办，**When** 覆盖安装本特性版本，**Then** 待办列表与全部统计数据原样保留。
2. **Given** 升级完成，**When** 检查本地存储，**Then** 存量自定义提示语行仍存在（应用不再读取），无任何 DELETE/清库操作发生。
3. **Given** 升级完成，**When** 正常使用应用，**Then** 无报错、无迁移失败提示。

---

### Edge Cases

- **空态二分**：完全没有启用条目 vs 有启用条目但今日均不轮到，是两种空态（引导添加 vs 告知今天没有），不得混用同一文案（见 US2 场景 2）。
- **升级瞬间的旧界面**：从旧版本升级后首次启动，提示语 Tab 直接消失，无迁移引导、无"功能下线"弹窗（数据未丢，无需解释）。
- **空态卡布局**：待办卡此前"空则整块隐藏（含前导间距）"，改为常驻后需保证与标题/倒计时的间距在空态与内容态一致，不出现跳动。
- **只读边界不变**：空态卡与内容卡一样不提供任何输入、勾选或跳转——5 秒场景不引入新交互。
- **提示语来源全部失效**：即使数据表残留自定义提示语、游标残留任意值、内置开关残留关闭态，拦截页行为完全一致（无提示语），残留值不产生任何可见影响。
- **无障碍服务主线程**：移除提示语取数后，覆盖层构建路径变短，不得引入新的异步等待（保持现有快照注入模式）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 拦截覆盖层 MUST NOT 展示任何提示语文本；内置提示语与自定义提示语两个来源全部停用。
- **FR-002**: 覆盖层内容自上而下 MUST 为：标题、今日待办卡片（含空态）、倒计时行、打开/取消按钮；待办卡片是唯一缓冲内容。
- **FR-003**: 今日无"轮到且启用"待办时，待办区 MUST 显示空态内容而非隐藏；空态 MUST 区分「无启用条目」（引导添加）与「有启用但今日不轮到」（告知今天没有轮到的待办）两种。
- **FR-004**: 今日待办全部完成时 MUST 保持现有"已全部完成"展示，不受本特性影响。
- **FR-005**: 应用 MUST 移除「提示语」Tab 与提示语管理页（底部导航 4→3），任何入口均不可达提示语管理功能，用户可见界面不再出现提示语相关文案。
- **FR-006**: MUST NOT 删除或清空存量自定义提示语数据（不删表、不清空行、不做破坏性迁移）；退役后应用 MUST NOT 再读写该数据。
- **FR-007**: 提示语循环游标与内置提示语开关的持久化值 MUST 停止读写；残留值 MAY 保留在本地存储中不清理。
- **FR-008**: 既有行为 MUST 零回归：拦截触发、5 秒减速带状态机、打开/取消/打断时序、事件流水记录、统计页（拦截与任务两块）、待办全部功能均不变。
- **FR-009**: 本特性 MUST NOT 触碰 `interception_events` 与 `todo_completions` 两张事件流水的表结构与数据。

### Key Entities *(include if feature involves data)*

- **自定义提示语池（退役）**：用户维护的持久提示语行；退役后数据只读保留在本地，应用不再读取。
- **内置提示语数组（退役）**：随包内置的固定文案资源；随特性一并移除出展示链路。
- **循环游标 / 内置开关（退役）**：提示语轮换进度与内置区启停的持久化值；停止读写，残留不清理。
- **今日待办卡片（升格）**：从"与提示语并行的内容之一"升格为拦截页唯一缓冲内容，新增两种空态分支；其余展示规则（D/T、前 3 条、截断、全完成态）不变。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四种待办状态（有未完成 / 全部完成 / 无启用条目 / 今日无轮到）下各触发拦截 ≥1 次，页面均不含提示语元素，且待办区均有可见内容。
- **SC-002**: 携带提示语与待办数据的旧版本覆盖升级后，待办、拦截事件、完成统计数据零丢失；本地存储中存量自定义提示语仍可查证存在。
- **SC-003**: 底部导航为 待办 / 统计 / 设置 三项，全应用遍历无提示语功能入口或文案。
- **SC-004**: 既有全部自动化测试通过（零回归）；提示语链路的既有测试随功能一并退役，退役后测试套件对 FR-001～FR-008 有对应覆盖。

## Assumptions

- 不提供「提示语→待办」批量转化或导出入口（方案 B2 已被否决，2026-09-24 拍板）。
- 空态文案为建议口径，实现时可调整措辞，语义不得改变（引导添加 / 告知不轮到）。
- 提示语数据表是否在未来版本物理删除：另行决策；本特性默认永久只读保留，与"数据只进不出"的项目红线一致。
- 5 秒状态机、减速带性格、统计口径、无障碍事件逻辑均不在本特性范围内。
- 底部导航 3 Tab 后各页内容与顺序不变（待办仍为默认页）。
