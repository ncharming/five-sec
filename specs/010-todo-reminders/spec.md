# Feature Specification: 待办到点主动提醒

**Feature Branch**: `010-todo-reminders`

**Created**: 2026-10-14

**Status**: Draft

**Input**: 用户经 /grill-me 两轮质询（11 + 5 问）后逐项拍板的口径——为待办新增到点主动提醒（响铃 + 震动，类闹钟体感），且**完全保留**现有两种提示逻辑（进入五秒 APP 时的待办展示、打开被拦截应用时的覆盖层今日待办卡片）不变。16 项拍板决策全文见 plan.md「决策记录」。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 为待办设置提醒时刻（Priority: P1)

用户给一条待办设定提醒时刻（如 18:30）：新建或编辑弹窗里设置；列表行副行能看到「提醒 18:30」；随时可改、可清除（关闭提醒回到原状）。不设时刻的待办行为与升级前逐位一致（零排程、零通知）。

**Why this priority**: 提醒时刻是一切的本体；「可设置、可编辑」是用户原始需求的第一条。

**Independent Test**: 新建待办设 18:30 → 行内出现「提醒 18:30」；编辑改为 07:00 → 行内随之变化；清除 → 角标消失、闹钟取消。

**Acceptance Scenarios**:

1. **Given** 新建弹窗，**When** 设置提醒时刻 18:30 并保存，**Then** 行内副行追加「提醒 18:30」，系统内已为下一个轮到日 18:30 排上闹钟。
2. **Given** 已设 18:30 的待办，**When** 编辑改 07:00，**Then** 排程重算为下一个轮到日 07:00，行内角标更新。
3. **Given** 已设提醒的待办，**When** 清除提醒并保存，**Then** 行内角标消失、该条不再参与任何排程。
4. **Given** 任意未设提醒的待办（含全部存量用户），**When** 升级后使用，**Then** 行为零变化（默认关）。

---

### User Story 2 - 到点主动提醒（无需进 APP / 触发拦截）（Priority: P1)

到达提醒时刻，无论用户在用别的应用还是屏幕已锁：五秒主动发出**类闹钟提醒**——全屏提醒页弹出（锁屏之上/亮屏横幅）、系统默认闹钟铃声（走闹钟音量流）、闹钟式持续震动。页内可逐条勾完成、可关闭；60 秒无操作自动停铃收进通知栏（点开仍可完成）。同一分钟多条待办聚合为一次响铃、一页列出。

**Why this priority**: 用户原始需求的第二、三条——「无需进入 APP 或触发拦截，主动发出」「响铃 + 震动」。

**Independent Test**: 设一条 2 分钟后的提醒 → 退到桌面/锁屏 → 到点亮屏弹全屏页 + 铃声 + 震动 → 页内勾完成（待办页同步变已勾）→ 页面自动关闭；不操作则 60 秒后停铃、通知栏留一条可点开的通知。

**Acceptance Scenarios**:

1. **Given** 一条今天轮到、未完成、设了 18:30 提醒的待办，**When** 18:30 到（屏幕任意状态），**Then** 全屏提醒页弹出、响系统闹钟铃声（闹钟音量流）、持续震动。
2. **Given** 提醒页上 3 条聚合条目，**When** 逐条勾选，**Then** 每勾一条待办页完成态同步（复用既有勾选双写口径），全勾完页面自动关闭、停铃。
3. **Given** 提醒页已弹出且用户无操作，**When** 60 秒后，**Then** 铃声/震动停止、页面关闭、通知栏留一条静默通知，点开仍能回到提醒页完成。
4. **Given** 三条待办都设 18:30 且当天都轮到未完成，**When** 18:30 到，**Then** 只响一次铃、一个提醒页列出三条（不是连环三响）。

---

### User Story 3 - 提醒与「轮到/完成」联动（Priority: P1)

提醒只在「今天轮到且启用」的日子响（复用 `TodoRecurrence.isDue` 同一判定）：每天规则每天响；每周几只在选中周几响；每 N 天拖延顺延期间持续每天响直到完成；停用不响；过期单次不响；**当天已完成的到点静默**（响前查库，勾完就不再打扰）。

**Why this priority**: 不联动的提醒会天天在同一时刻轰炸「今天不用做」的待办，两周内必被用户卸载——联动是本功能不变成垃圾通知源的前提。

**Independent Test**: 每周一规则 + 周一 18:30 提醒 → 周二到点不响、下周一响；当天 15:00 勾完成 → 18:30 静默；17:00 取消完成 → 18:30 照常响。

**Acceptance Scenarios**:

1. **Given** 「每周一/周五」待办设 18:30，**When** 周三 18:30，**Then** 不响（isDue=false）。
2. **Given** 每 3 天待办已到期未完成（顺延期），**When** 到点，**Then** 每天连续响，直到某天完成后从次日起停 N 天。
3. **Given** 当天已勾完成且时刻未到，**When** 到点，**Then** 静默跳过（不响铃、不弹页）。
4. **Given** 待办被停用或为过期单次，**When** 到点，**Then** 不响。

---

### User Story 4 - 权限引导（Priority: P2)

首次保存提醒时刻时请求通知权限（Android 13+）；精确闹钟（12+）与全屏显示（14+）需到系统设置开启——待办页顶部横幅按缺失项逐条提示「去开启」，开启与否不阻断保存（拒绝只降级：不精确/不弹全屏/通知不显示），横幅在用户补授权后自动消失。

**Why this priority**: 类闹钟提醒链路横跨三个版本门限的权限；硬阻断违背纯离线工具性格，无引导则用户以为功能坏了。

**Independent Test**: 首次保存提醒时刻弹出通知权限请求 → 拒绝 → 横幅出现「通知权限未开启…」→ 去设置补开 → 返回横幅消失；关闭「闹钟和提醒」开关 → 横幅提示「提醒时间可能不准」。

**Acceptance Scenarios**:

1. **Given** Android 13+ 且未授权通知，**When** 首次保存提醒时刻，**Then** 弹通知权限请求；拒绝后保存成功、横幅持续提示。
2. **Given** Android 12+ 且「闹钟和提醒」未开，**When** 查看待办页，**Then** 横幅提示可能不精确（闹钟自动降级为非精确、仍会响）。
3. **Given** 任一缺失权限被补齐，**When** 回到待办页，**Then** 对应横幅消失。

---

### Edge Cases

- **时刻已过仍允许保存**：允许保存过去/今日已过时刻，但绝不补响——重复类从下一个轮到日起算；单次若完整时间点已过提醒自然落空（待办本身仍有效）。改时刻/启停/删除/改规则/复活均即时重排。
- **重启/更新/时钟变更**：闹钟由系统持有、进程死亡不受影响；重启、应用更新、系统时间/时区被改都会清掉/漂移闹钟——`RECEIVE_BOOT_COMPLETED` + `TIME_SET` + `TIMEZONE_CHANGED` + `MY_PACKAGE_REPLACED` 广播全量重排，另每次进 App 兜底重排；**强停（force-stop）后闹钟全清且收不到广播**是系统机制，已知限制写 README（用户重新打开 App 即自愈）。
- **错过的提醒不补响**：关机/被 ROM 拦截导致某次没响，恢复后静默跳过已过时刻，只排未来（「宁可不提醒不惊吓」）。
- **勿扰模式**：不申请穿透；DND 下按系统默认行为（大概率静默/仅亮屏）；README 说明用户可自行把五秒加入「闹钟可中断勿扰」例外。
- **权限降级组合**（修复轮三后）：13+ 无通知权限 → 通知不显示但**仍响铃震动**（响铃前台服务 + 页面补拉不依赖通知可见性）；14+ 未放行全屏显示 → 息屏不弹全屏页（高分横幅 + 响铃震动仍在，亮屏补拉不依赖此权限）；未忽略电池优化 → 国产 ROM 息屏可能冻结进程，闹钟广播收不到（代码层绕不过，横幅一键引导白名单；调度层 setAlarmClock 已无可再降级项）。
- **响前二次判定**：闹钟到点后以触发时刻的本地 HH:mm 反查全量待办（非仅排程条目），完成/停用/删除发生在排程后、到点前的变更全部被最新数据库状态吸收。
- **过期单次已完成跨日清理**（既有惰性删除）与提醒无冲突：行没了，重排自然不再排它。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每条待办 MUST 支持可选提醒时刻（HH:mm，24 小时制，秒恒 00）：新建/编辑弹窗可设置、可修改、可清除；空 = 无提醒 = 与升级前行为逐位一致。重复类 = 每个轮到日该时刻提醒；单次 = 有效期日当天该时刻提醒。
- **FR-002**: 到点提醒 MUST 无需进入 APP 或触发拦截、**也无需点击通知**即主动发出：响铃前台服务（Receiver 到点直接启动）先响系统默认闹钟铃声（ALARM 音量流、循环）+ 闹钟式持续震动，与页面拉起与否解耦（息屏/亮屏/FSI 被拒都即时响）；全屏提醒页（息屏 FSI 直拉 + 亮屏服务补拉）锁屏之上显示/自动亮屏；零内置音频文件。
- **FR-003**: 提醒触发 MUST 只作用于「启用 && 今天轮到 && 当天未完成」条目（`TodoRecurrence.isDue` 同源判定 + 响前查库）；同一分钟多条 MUST 聚合为一次响铃/一页展示。
- **FR-004**: 提醒页 MUST 展示条目**完整内容**（多行原文不截断）并支持逐条「完成」按钮（复用仓库勾选双写口径：todos 行 + todo_completions 事件）与关闭；全部勾完 MUST 自动关闭；60 秒无操作 MUST 自动停铃并收进静默通知（点开可回提醒页完成）。「勾选仅在待办页」口径扩展为「待办页与提醒页」。
- **FR-005**: 排程 MUST 只面向未来（绝不补响已过时刻）；时刻/规则/启停/删除/复活的每次变更 MUST 即时重排；重启/应用更新/时间与时区变更 MUST 触发全量重排；每次进入 App MUST 兜底重排。
- **FR-006**: 权限策略：调度用 `AlarmManager.setAlarmClock()`（修复轮三拍板：闹钟类应用专用 API，触发时系统退出 Doze、**不需要任何精确闹钟权限**，状态栏常驻即将闹钟图标）；引导**忽略电池优化**（国产 ROM 息屏冻结进程连广播都收不到，一键弹窗 `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`）；`POST_NOTIFICATIONS`（13+ 首次保存提醒时刻时请求；拒绝不阻断、仍响铃）；`USE_FULL_SCREEN_INTENT`（14+ 引导设置放行）；待办页横幅按缺失项提示；MUST NOT 申请勿扰穿透。
- **FR-007**: 提醒 MUST NOT 留任何痕：不写 `interception_events`、不写 `todo_completions`（勾完成的事件除外——那是既有勾选口径）、不提供「已提醒」标记、不进统计。
- **FR-008**: 现有两种提示逻辑（进入五秒 APP 时的展示、拦截覆盖层今日待办卡片）MUST 零改动：无障碍服务、拦截状态机、覆盖层 UI 与统计口径一行不碰。
- **FR-009**: 升级迁移 MUST 零丢失：todos 新增 `reminderTime` 一列（TEXT NOT NULL DEFAULT ''），存量行空串 = 无提醒；MUST 配套手建库迁移测试；MUST NOT 破坏性迁移。
- **FR-010**: 时间口径 MUST 沿用 TimeProvider 注入 + 设备本地时区；「下次提醒时刻」计算 MUST 是零 Android 依赖的纯函数并配单测（含跨日边界/时区显式传入）；MUST NOT 引入任何网络/分析依赖或新 Gradle 依赖。

## Success Criteria *(mandatory)*

- **SC-001**: 设 18:30 的每天待办：当天 18:30 全屏页 + 铃声 + 震动；勾完成页自动关；改时刻/清除即时生效。
- **SC-002**: 不轮到的日子（周几规则非选中日）、停用、过期单次、当天已完成：到点全部静默。
- **SC-003**: 同一分钟三条待办只响一次、一页三条；60 秒无操作停铃收通知，通知点开可完成。
- **SC-004**: 重启设备后闹钟仍在（开机重排）；强停后不响是已知限制（README 记载）；权限三项各有横幅引导、补齐即消失。
- **SC-005**: 存量用户升级后零感知（无提醒时刻 = 无任何新行为）；拦截覆盖层/待办页既有交互逐位不变。
- **SC-006**: `gradle :app:assembleDebug` 与 `:app:testDebugUnitTest` 全绿；Planner 纯逻辑判定表、v9→v10 手建库迁移测试、仓库提醒列口径测试齐备；README/AGENTS 口径同步。

## Assumptions

- 提醒时刻用户输入界面用 Material3 TimePicker（24 小时制，分钟精度），秒恒 00 不暴露。
- 全屏提醒页视觉沿用四页统一语言（FiveSecTheme 浅色体系），锁屏上显示、自动亮屏、不进最近任务。
- 通知小图标用内置矢量（时钟图形）；铃声/震动全走系统资源。
- OEM 省电策略对 AlarmManager 的干扰与无障碍服务同源（README 平台限制段统一说明）；本功能不做任何对抗系统的保活。
