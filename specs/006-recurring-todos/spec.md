# Feature Specification: 重复待办（按星期几 / 每 N 天间隔）

**Feature Branch**: `006-recurring-todos`

**Created**: 2026-09-23

**Status**: Draft

**Input**: User description: "在 specs/005 每日待办基础上增加可配置的重复规则——每条待办三选一：每天（默认，现状行为）；按星期几（多选周一~周日，仅选中日期轮到，全不选不允许保存）；每 N 天（N=2~365，滚动节奏：从未完成视为到期立即可做，完成后从完成日起算隔 N 天再次轮到，到期后持续轮到直到完成）。不轮到的日子：待办页条目灰显并标注「今天不用做」、不可勾选，条目不消失；完成进度 D/T 分母只数「轮到且启用」条目；拦截覆盖层卡片只显示轮到的条目。完成判定保持「最近完成日 == 今天」惰性求值；切换规则不清锚点（锚点=最近完成日，从未完成=创建日）；存量数据升级零感知（自动归入每天），零丢失。"

## User Scenarios & Testing *(mandatory)*

<!-- courteously ordered by importance; each story independently testable -->

### User Story 1 - 按星期几重复（Priority: P1)

用户有些事不是每天都要做：工作日任务、隔天锻炼日。用户把一条待办的重复规则设为「按星期几」并勾选周一/周三/周五。只有这些日子这条待办才"轮到"——可以勾选、计入完成进度、出现在拦截提醒卡片里；其余日子条目仍躺在清单里，但灰显标注「今天不用做」，不可勾选、不计进度、不上拦截卡片。

**Why this priority**: 用户明确提出的第一诉求（"周一三五锻炼"是最常见的非每日节奏），价值最直接。

**Independent Test**: 建多条待办分别只勾一个星期几，逐日（或调整系统日期）验证轮到/不轮到两侧的展示、勾选、进度计数与拦截卡片行为。

**Acceptance Scenarios**:

1. **Given** 一条待办规则为「周一三五」，**When** 周三打开待办页，**Then** 该条目正常展示、可勾选，计入完成进度分母。
2. **Given** 同一条待办，**When** 周四打开待办页，**Then** 条目灰显并标注「今天不用做」，勾选框不可用，不计入分母，条目未消失（仍可改名/删除/停用）。
3. **Given** 同一条待办，**When** 周四触发拦截，**Then** 覆盖层待办卡片不出现该条目。
4. **Given** 规则编辑中取消全部星期几，**When** 尝试保存，**Then** 保存被拒绝并提示至少选择一天。

---

### User Story 2 - 每 N 天间隔重复（Priority: P2)

用户有些事按间隔循环：每 3 天换一次床单、每 7 天给植物施肥。用户把规则设为「每 3 天」：从未完成过时立即轮到（立即可勾）；完成后从完成当天整日起算，接下来两天不轮到（灰显「今天不用做」），第 3 天重新轮到且回到未完成；若一直拖着不做，它保持轮到状态持续提醒——滚动节奏，拖延只会顺延，不会"错过就没"。

**Why this priority**: 第二常见节奏；滚动语义是用户明确拍板的口径，覆盖周期性家务/养护类场景。

**Independent Test**: 建「每 3 天」待办，完成一次后逐日观察其后 3 个自然日的轮到状态与第 3 天的自动复位；再验证到期未完成时长挂不消失。

**Acceptance Scenarios**:

1. **Given** 一条从未完成的「每 3 天」待办，**When** 当天查看，**Then** 立即轮到、可勾选。
2. **Given** 该待办今天已勾选完成，**When** 明天与后天查看，**Then** 灰显「今天不用做」、不可勾、不计分母、不上拦截卡片。
3. **Given** 完成后到达第 3 天，**When** 打开待办页，**Then** 重新轮到且为未完成。
4. **Given** 到期后连续 5 天未完成，**When** 第 6 天查看，**Then** 仍为轮到状态（持续提醒，不自动隐藏）。

---

### User Story 3 - 老数据升级零感知（Priority: P3)

已在使用每日待办的用户覆盖升级应用：所有既有条目原样保留，自动归入「每天」规则，勾选状态、启用开关、完成状态全部不变，界面行为与升级前完全一致。

**Why this priority**: 是回归保障而非新价值；实现顺序靠前（数据层先行），但验收优先级最低。

**Independent Test**: 用旧版本建多条待办并勾选其一 → 覆盖安装新版本 → 检查条目、状态、每日重置行为与升级前一致。

**Acceptance Scenarios**:

1. **Given** 旧版本存在若干条待办（含启用/停用、今天已勾选），**When** 覆盖升级后首次打开，**Then** 条目数量、文本、启用状态、完成状态与升级前一致。
2. **Given** 升级后的既有条目，**When** 查看其重复规则，**Then** 均为「每天」且跨日自动重置行为不变。

---

### User Story 4 - 规则随时可改（Priority: P3)

用户随时能进入一条待办的编辑界面查看和修改它的重复规则；改动即时生效（今天轮不轮到立即重算）；切换规则不重置历史——滚动锚点恒按「最近完成日（从未完成=创建日）」计算，完成状态不被清除。

**Why this priority**: 保障规则体系可用与可逆，避免"设错一次只能删了重建"。

**Independent Test**: 对同一条待办依次切换三种规则，验证当日轮到状态即时重算、完成状态与滚动锚点延续。

**Acceptance Scenarios**:

1. **Given** 一条今天已完成的「每天」待办改为「每 3 天」，**When** 保存后查看，**Then** 完成状态保持；锚点=今天（最近完成日），其后 2 天灰显、第 3 天重新轮到。
2. **Given** 一条「每 3 天」待办改回「每天」，**When** 保存后查看，**Then** 每天轮到（今天若已完成则显示已完成）。

---

### Edge Cases

- 周几规则一个日子都没选 → 不可保存（表单拦截 + 提示），不产生永远灰显的死条目。
- 每 N 天的 N 边界 → N 最小 2（1 等价于「每天」，不重复提供）、最大 365；越界输入以边界值收敛。
- 今日没有任何轮到的启用条目 → 拦截卡片整块隐藏（与"启用数为 0"同待遇）；待办页列表仍展示（灰显）这些条目。
- 混合规则清单的完成计数 → 分母只数「轮到且启用」；历史完成的不轮到条目不进分子。
- 跨日重算 → 全部轮到判定按设备本地时区自然日惰性求值，无后台清理任务。
- 停用与轮到的叠加 → 停用条目无论轮不轮到都不进卡片、不进分母（两道过滤独立生效）。
- 每 N 天完成当天 → 完成后立即进入灰显期（间隔自完成日整日起算，第 N 天重新轮到）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每条待办 MUST 拥有重复规则，且只能三选一：每天 / 按星期几 / 每 N 天；新建默认「每天」。
- **FR-002**: 按星期几规则 MUST 支持在周一至周日中多选（至少一天）；一个都不选时 MUST 无法保存并给出明确提示。
- **FR-003**: 每 N 天规则的 N MUST 限定在 2~365；MUST 采用滚动节奏：从未完成过视为到期；完成后自完成日整日起算第 N 天再次轮到；到期后 MUST 保持轮到直到完成。
- **FR-004**: 「轮到」判定 MUST 按设备本地时区自然日惰性求值，MUST NOT 引入后台任务、闹钟或通知。
- **FR-005**: 不轮到的日子，待办页条目 MUST 灰显并出现「今天不用做」标注，MUST 不可勾选；条目 MUST NOT 从清单消失，且仍可重命名、删除、启用/停用。
- **FR-006**: 完成进度计数（如「今日待办 D/T」）分母 MUST 仅含「轮到且启用」的条目，分子为其中已完成数；不轮到或停用的条目 MUST NOT 计入分母或分子。
- **FR-007**: 拦截覆盖层待办卡片 MUST 仅展示轮到的条目（未完成条目列表与计数口径同源）；今日无任何轮到的启用条目时卡片 MUST 整块隐藏。
- **FR-008**: 完成判定 MUST 保持「最近完成日 == 今天」语义不变；修改规则 MUST NOT 改变某条"今天已完成"的既成状态。
- **FR-009**: 修改规则 MUST 即时生效（当日的轮到状态立即重算）；切换规则 MUST NOT 清除最近完成日；滚动锚点恒等于「最近完成日，从未完成则为创建日」。
- **FR-010**: 存量数据升级 MUST 零丢失、零感知：既有条目全部保留并自动归入「每天」规则，文本、启用状态、完成状态不变；升级 MUST 以不丢数据的方式完成并配套升级前后回归验证，MUST NOT 使用破坏性兜底。
- **FR-011**: 待办及重复规则 MUST NOT 引入网络、通知、闹钟或任何新权限；MUST NOT 进入统计页、MUST NOT 影响连续天数语义。
- **FR-012**: 勾选仍 MUST 仅发生在待办页；拦截覆盖层待办卡片保持只读（specs/005 契约不回退）。

### Key Entities *(include if feature involves data)*

- **待办（Todo，扩展）**：既有字段（自增 id、标题文本 ≤200 字、启用开关、最近完成日）之上新增——重复规则类型（每天/按星期几/每 N 天）、星期几选择集（周几规则用）、间隔天数 N（间隔规则用，2~365）、滚动锚点日（最近完成日为空时=创建日，间隔规则起算基准）。完成判定仍是最近完成日等于今天。
- **今日待办快照行（TodayTodo，扩展）**：覆盖层卡片行——文本、今日是否已完成之外新增"今天是否轮到"（卡片按此过滤与计数）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 「周一三五」待办：周三可勾且计入进度；周四灰显「今天不用做」、不可勾、不计进度；周四拦截卡片不出现该条——三个观察点全部成立。
- **SC-002**: 「每 3 天」待办完成一次后连续 2 天灰显，第 3 天重新轮到且为未完成；到期后放置任意天数不消失、保持可勾。
- **SC-003**: 混合清单（如启用 5 条、当日轮到 2 条）的拦截卡片计数分母为 2，未完成条目列表仅含轮到项。
- **SC-004**: 覆盖升级后既有条目零丢失，规则均为「每天」，每日重置行为与升级前一致（旧库升级可验证）。
- **SC-005**: 周几选择被清空时保存被拒绝且出现提示；N 越界输入收敛到 2~365。
- **SC-006**: 既有全部自动化测试零回归；新增重复规则逻辑（周几/间隔/边界/时区）与数据升级均有测试覆盖，编译通过。

## Assumptions

- "每天/某天/第 N 天"均按设备本地时区自然日；不做时区穿越补偿。
- 三种规则互斥，不提供「周几 + 间隔」组合，也不提供「每月几号」（范围外）。
- 间隔规则锚点不可手动指定（如固定日历格点），一律滚动起算（用户拍板口径）。
- 不做"提前完成未来某天"；不轮到的条目不可勾是刻意的（保持「今天的事」语义）。
- 规则编辑不改变覆盖层只读约定与拦截流程时序（specs/005 契约不动）。
- 「今天不用做」为灰显标注的占位文案，最终文案以资源文件为准。
