# Feature Specification: 各应用历史数据（日/周/月/年）+ 统计模块去冗余

**Feature Branch**: `003-stats-history-ranges`

**Created**: 2026-09-09

**Status**: Draft

**Input**: User description: "对统计模块进行重构：需要保证用户从第一次安装使用后，所有的数据都留存下来，除非用户手动卸载了。1. 上面部分展示不变：保持今日拦截、今日取消、今日打开、连续完成天数不变。2. 各应用今日数据需要改变：改为各应用历史数据。2.1 按照天、周、月、年展示：每个分类下继续按照目前的情况展示。2.2 认为引入 sqlite 改造是最快的。"

**Builds on**: [001-app-intercept-exercise](../001-app-intercept-exercise/spec.md) 与 [002-app-search-perapp-stats](../002-app-search-perapp-stats/spec.md)。本特性不改动拦截机制、目标清单、权限流程与顶部"今日概览"，仅重构统计页的"各应用数据"区域（今日 → 历史）并清理统计模块冗余路径。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按日/周/月/年查看各应用历史数据 (Priority: P1)

用户打开统计页时，顶部"今日概览"保持原样；下方原"各应用今日数据"区域升级为"各应用历史数据"：提供 **日 / 周 / 月 / 年** 四个时间档位，默认选中"日"（首屏与现状一致）。选中任一档位后，页面为当前拦截清单中的每个应用展示一张品牌色卡片，卡片内容为该应用在所选周期内的 **拦截次数 / 打开次数 / 取消次数** 三个指标，卡片样式沿用现状。

周期口径为**自然周期**（按设备本地时区）：日 = 今天零点起；周 = 本周（周一零点起）；月 = 本月（1 号零点起）；年 = 本年（1 月 1 日零点起）。

**Why this priority**: "只看今天"无法回答"我这周/这个月刷了多少次抖音"这类更有价值的自我审视问题。历史视角是本次需求的直接目标，也是唯一新增的用户可见能力，因此为 P1。

**Independent Test**: 本周一以来对小红书拦截 10 次、打开 6 次、取消 4 次；打开统计页切到"周"，验证小红书卡片显示 拦截 10 / 打开 6 / 取消 4，且使用小红书品牌色。

**Acceptance Scenarios**:

1. **Given** 用户进入统计页，**When** 页面加载完成，**Then** 顶部四项（今日拦截/今日取消/今日打开/连续完成天数）与改造前完全一致，下方显示"各应用历史数据"区域且默认选中"日"档。
2. **Given** 统计页已显示，**When** 用户选择"周"档，**Then** 每个清单应用卡片显示本周（周一起）的 拦截/打开/取消 计数，卡片文案不出现"今日"字样。
3. **Given** 今天是周日，**When** 用户查看"周"档，**Then** 统计范围从本周一零点开始（周日属于当期自然周的最后一天，而非上一周）。
4. **Given** 用户选择"月"档，**When** 查看，**Then** 计数自本月 1 号零点起累计；选择"年"档同理自 1 月 1 日起。
5. **Given** 所选周期内某应用无任何拦截记录，**When** 查看，**Then** 该应用卡片仍显示（沿用清单应用全列出），三个计数为 0。
6. **Given** 用户在档位间来回切换，**When** 每次切换，**Then** 数据即时更新（无可感知延迟），无需手动刷新。

---

### User Story 2 - 历史数据自首次使用起完整留存 (Priority: P2)

用户自首次安装使用起产生的**所有**拦截记录都被完整保留，并参与任意档位的统计——除非用户手动卸载应用（卸载导致数据清空属平台预期行为）。应用升级、系统版本升级、设备重启等场景均不丢失、不清理任何历史记录。

**Why this priority**: 历史统计的前提是历史数据完整。数据一旦丢失，任何档位的展示都是错误的。它是 P1 的地基，但当前实现已具备"只增不删"的存储事实，本故事的价值在于把它固化为可验证的保障并守住升级不丢数据的红线，因此为 P2。

**Independent Test**: 人为构造跨越数月（含跨年）的历史拦截记录后，"年"档计数 = 全部构造记录的真实聚合；随后执行应用升级（数据库版本变迁），记录数量与聚合结果不变。

**Acceptance Scenarios**:

1. **Given** 设备上存在安装首日至今的拦截记录，**When** 用户查看"年"档，**Then** 所有历史记录都参与计数（包括很久以前的）。
2. **Given** 应用进行版本升级（内部存储结构版本提升），**When** 升级后首次打开统计页，**Then** 全部历史记录仍在，各档位计数与升级前一致。
3. **Given** 用户删除清单中的某个应用，**When** 查看任意档位，**Then** 该应用不再展示卡片，**And** 其历史记录仍完整保留在存储中（重新添加后历史再现）。

---

### User Story 3 - 统计模块去冗余（单一数据源） (Priority: P3)

移除统计模块中遗留的冗余汇总路径：不再在每次拦截发生时额外维护一份"按应用累计汇总"的存储，统计页所有数字均由事件流水实时聚合得到，统计模块只保留**单一数据源**。

**Why this priority**: 纯内部质量改进，无直接用户可见价值，但消除双写可减少存储冗余与维护成本，并杜绝两条路径数据不一致的可能。它不影响 P1/P2 的用户价值，放在最后执行。

**Independent Test**: 移除冗余路径后，顶部今日四卡与各档位应用卡片全部回归通过；不再存在对汇总表的任何读写。

**Acceptance Scenarios**:

1. **Given** 冗余汇总路径已移除，**When** 发生一次新的拦截，**Then** 仅事件流水新增一条记录，无其他存储被更新。
2. **Given** 老版本升级上来（设备上存在冗余汇总表），**When** 应用完成升级，**Then** 冗余表被安全清除，事件流水与各档位统计不受影响。

---

### Edge Cases

- **周期内零记录**：所选档位下没有任何拦截事件时，清单应用卡片保持显示、计数为 0（沿用现状，不引入额外空态）。
- **周日查看"周"**：周期从本周一零点起算，包含当天（周日是本周最后一天）。
- **页面停留跨周期**：跨日/跨周/跨月/跨年时页面不自动刷新（与现状一致），重新进入页面生效。
- **时区**：周期边界按设备当前本地时区计算；跨时区旅行后以新时区为准。
- **中断事件口径**：结果为"中断"的事件计入拦截总数，但不计入打开数与取消数（沿用现状）。
- **卸载重装**：数据清空、从零重新累计（用户已确认接受，不做云备份增强）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 统计页"各应用数据"区域 MUST 提供 日/周/月/年 四个时间档位切换，默认选中"日"。
- **FR-002**: 周期口径 MUST 为自然周期（设备本地时区）：日=当天零点起；周=本周一零点起；月=本月 1 号零点起；年=本年 1 月 1 日零点起。
- **FR-003**: 每个档位下，每个清单应用 MUST 展示该周期内的 拦截次数 / 打开次数 / 取消次数。
- **FR-004**: 顶部"今日拦截 / 今日取消 / 今日打开 / 连续完成天数"四项 MUST 与改造前完全一致（零行为变化）。
- **FR-005**: 全部拦截记录 MUST 自首次使用起持续留存并参与统计，除用户卸载外不得有任何清理路径。
- **FR-006**: 应用历史卡片 MUST 仅展示当前拦截清单内的应用；清单外应用的历史数据仍留存但不展示。
- **FR-007**: 非"日"档位下，应用卡片指标文案 MUST NOT 含"今日"字样（使用通用文案），避免口径误导。
- **FR-008**: 统计数据 MUST 以事件流水为单一数据源；冗余的按应用累计汇总路径及其存储 MUST 移除（老设备升级时安全清理）。
- **FR-009**: 档位切换 MUST 即时生效并在本地完成计算，无可感知延迟。

### Key Entities *(include if feature involves data)*

- **拦截事件**（已存在，语义不变）：某次尝试打开目标应用的记录——所属应用、发生时间、结果（打开/取消/中断）、是否完成锻炼。历史统计的唯一事实来源。
- **统计档位**（新增概念）：日/周/月/年四个自然周期的枚举，用于界定聚合的时间起点。
- **应用周期聚合**（派生值，不落库）：某应用在某档位周期内的 拦截/打开/取消 计数，由拦截事件实时聚合得到。
- **应用累计汇总**（待移除实体）：按应用累计的冗余汇总存储，本特性删除。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 任一档位切换后，对应数据在 1 秒内呈现（本地计算）。
- **SC-002**: 任意档位下每个应用的三个计数与该周期内实际拦截事件逐条核对一致（100% 准确）。
- **SC-003**: 顶部今日四卡与连续天数在改造前后零差异（回归验证）。
- **SC-004**: 统计相关自动化测试全部通过，其中包含周期边界（周一/月初/年初/跨年/周日）与历史完整性（跨月数据）的测试用例。

## Assumptions

- 自然周期口径（周一起始）已由用户确认。
- 允许通过一次存储结构升级安全移除冗余汇总表；事件流水结构不变。
- 卸载即清空、不做云备份增强；系统默认备份机制保持现状。
- 页面停留期间跨周期不自动刷新（与现状一致，不做定时刷新）。
- "历史数据留存"指存储完整；展示范围仍以当前拦截清单为准（见 FR-006）。
